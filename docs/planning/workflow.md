# Whomi 产品工作流程 · 试行第 1 版

自 2026-11-04 起用于本地产品协作。每个新功能保留一个编号，主记录保存在 `ideas/`。在新聊天接手时，先看当前状态、最近决定和下一步，再核对本次指令。维护者决定产品目标、优先级、实施范围与效果结论，代理执行已授权的工作。

| 时机 | 操作与结束条件 |
|---|---|
| 提出想法 | 查重后用[想法模板](idea-template.md)记录原意、场景、状态和下一步，加入[索引](README.md)。只想留存时停在「待评估」。 |
| 评估 | 收到评估请求后转为「评估中」。核对已有能力，对较大功能按仓库约定调研现成方案、复用机会及剩余成本。影响选型的试验先说明投入和通过条件，由维护者决定是否执行。 |
| 安排路线 | 维护者选择阶段目标和顺序后，在根目录路线图 `ROADMAP.md` 记录目标、理由、阶段和编号。目标版本可待定。排到下一阶段的项仍需核对开工授权。 |
| 确认与实施 | 将确定的方案标为具体版本，如「方案第 1 版」。记录本轮包含和排除的行为、可观察的验收场景、材料范围和维护者的决定。范围与顺序已确定时标「待实施」，有明确开工授权后核对分支再转「实施中」。已有授权可跨聊天延续。 |
| 验收与交付 | 达到约定范围后转「待验收」。逐项写实际结果、检查依据与遗留问题。失败回到「实施中」并保留复现材料。验收通过后记录真实交付产物与日期，转「待回看」，约定由谁在什么情况下回看。 |
| 回看 | 把试用观察与最初问题逐项对照。维护者确认目标达成、剩余事项得到处理或决定停止后，记录依据并标「已闭环」。效果证据不足时保留「待回看」及下一步。 |

在任一适用阶段，维护者可选择「暂缓」或「不采纳」。写明理由，暂缓项再记重启条件。每次状态变化写一行日期、决定依据与下一步，关联已有的研究、设计、开发计划或验收记录。

**需要重新确认的变化。** 面向用户的范围、材料访问权限或验收标准发生变化时，只暂停受影响的部分。说明差异和代价，由维护者确认新版范围。范围内的实现细节、测试和修复沿用原授权。代理在主记录中转述维护者的决定，单独改写状态字段不能取得授权。

**交接示例。** 第 001 条当前只要求保留朋友与工作交流的差异。「评估 001」允许比较现有取材方式。「按第 1 版方案实现 001」适用于已经存在且明确确认的第 1 版。假设该版只准使用用户选定的两段材料，新增「后台扫描所有会话」需另行确认。即便展示通过验收，仍要等试用者能说明自己从哪些经历中看到了差异，再据实回看效果。

**执行边界。** 以上是代理应遵守的工作约定。写入权限和远端合并权限由各自的运行环境控制。关于只读评估、受保护的批准依据、独立检查和合并控制，见[技术约束提案](workflow-proposal.md#路线确认与代理约束)。
