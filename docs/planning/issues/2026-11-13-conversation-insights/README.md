## 设计和范围约束

- I01、I05、I06、I07、Q00、H00均明确要求使用 **impeccable**、**ui-ux-pro-max**、**design-review**；执行阶段与证据见[技能约定](../../../designs/conversation-insights/ui-skill-workflow.md)。实际页面审查须在实现后执行，当前图稿确认不记为运行验收通过。
- 同布局补充状态、常规窄窗和文字换行复用已选结构，不逐项重新选图。真正新增或修改图稿使用design-shotgun，按一页讨论、确认并入工单后再下一页的顺序。
- 洞察不调用检索增强生成；问一问和心事屋只保留入口，新功能分别在独立计划推进。键值缓存专项优化留待后续。
- 成功新增或删除洞察报告必须同步个人总览；整个会话删除还需清理关联报告、原文和失效阅读状态。示例：删除小林十月报告不影响九月报告，撤回十月贡献后只按剩余依据计算。
- 报告默认名称固定为会话洞察，支持手动改名；生成内容称对方ta；本人未确认时拦截会话内入口，历史报告仍可阅读。

## 发布核对与后续工作

发布前核对图稿覆盖、需求一致性、链接、依赖与重复工单；正文使用可访问的固定版本文档和图片链接，发布后回填真实工单号。本轮不创建合并请求、不修改产品代码。

实施前须在对应工单落实名称长度与保存中交互、失败行返回目标、个人总览聚合契约；这些是规则与接口待办，不是缺少新页面。真实云端比较先约定模型、材料和费用。
