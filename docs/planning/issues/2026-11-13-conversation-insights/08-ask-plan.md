# 问一问：明确业务流程、资料检索与页面实施计划

本地草稿编号：Q00。后续独立规划工单，不包含功能编码，不阻塞首期对话洞察。

## 目标与现状

明确问一问如何帮助用户理解自己和关系，完成需求、现成方案比较、页面设计和可实施任务拆分。未来可使用检索增强生成：先从允许使用的聊天或报告中找到相关材料，再交给模型回答。资料范围、索引方式和模型尚未选定；对话洞察本身不依赖这套检索。

当前已有澄清问题的页面、回答与撤回适配接口，以及本次运行的前端状态；正式应用尚未接入真实问题生成和持久化。先核对它与用户设想的问一问是否一致，优先复用现有页面，不把现有澄清界面当成已完成的通用问答。

## 需求与取材边界

以下均为待讨论的虚构场景，用于确认流程，不代表已批准功能：

| 场景 | 要明确的行为与完成标准 |
|---|---|
| 用户主动问为什么我们每次约见面都不愉快 | 是否属于问一问；若属于，明确输入、回答和来源回查流程。 |
| 模型看到同一行为有两种解释，向用户澄清 | 是否保留现有澄清方向；若保留，明确回答怎样修正认识、保存和撤回。 |
| 用户只允许读取小林的十月记录 | 检索不能取用其他会话或日期；无相关依据时不得把旧分析当作原文事实。 |
| 用户撤回回答或删除来源报告 | 明确已存回答、检索材料和后续判断如何更新，不能继续引用已经撤销的来源。 |

- [ ] 确认是用户主动提问、模型向用户澄清，还是明确区分两条流程；不承诺未经确认的问题频率。
- [ ] 明确允许读取哪些会话、报告和回答，用户如何更改范围，以及无材料、无相关结果和未建索引时的行为；不默认全库读取。
- [ ] 区分原文观察、报告解释与用户补充；旧判断被修正后，检索结果和新回答应使用有效版本。
- [ ] 将正常、输入保留与重试、撤回、来源删除的预期结果写入独立规格。

## 现成方案与最小验证

- [ ] 按可直接使用的完整产品、少量改造产品、可复用组件顺序筛选，深入最相关的至多三个候选；不足三个说明原因。
- [ ] 附官方仓库、文档及核查版本，比较适用场景、许可证、维护活跃度、部署与升级负担、资料隐私、费用和迁移成本；区分官方声明与实际核查，不以关注数代替用户规模。
- [ ] 每个候选用上表中的一个场景说明可直接完成什么、还需改造什么，给出采用、复用、必须自行实现的清单与推荐。
- [ ] 与 H00 共用一份检索方案：是否需要语义索引、是否需要把文字转换为检索向量的嵌入模型、本地或云端运行、何时建立与更新索引、来源撤销后如何失效。不得要求用户先完成索引才能使用首期洞察。
- [ ] 只对会改变选型的疑点提出最小验证，说明通过标准、模型与材料、费用上限和停止条件，获得用户同意后执行；本工单发布不授权收费试验。

## 页面设计与后续拆分

- [ ] 需求和选型确认后，使用 **design-shotgun** 设计需要新增或改版的界面。逐个讨论：展示一页、用户确认、附入对应工单，再讨论下一页；已有可复用布局不重复选图。
- [ ] 每份选定图附状态映射和验收场景，覆盖经确认流程中的正常、无材料、失败恢复、撤回及常规窄窗；同布局简单状态可复用组件，不机械增加图稿数量。
- [ ] 使用 writing-plans 形成实施版计划，明确接口、文件职责、依赖及必要测试；方案确认后再拆功能开发子工单。本工单完成不代表功能已实现。

## 必用界面技能与证据

界面设计与后续实现工单必须列明以下三项，执行阶段及留证方式遵守[界面技能约定](../../../designs/conversation-insights/ui-skill-workflow.md)：

- **impeccable**：依据既有系统和选定图组织页面，保留设计依据、选图及状态对应关系。
- **ui-ux-pro-max**：核查经确认的输入与回答流程、错误恢复、键盘焦点、对比度及桌面窄窗，记录适用于 Electron/React 的建议和处理结果。
- **design-review**：在后续页面实现后审查真实运行截图，修复后复查，保存前后截图与未验证项；静态选图不记为运行审查通过。

示例：若确定保留澄清流程，回答提交失败后输入仍在，重试操作可用且焦点可追踪；这一行为应进入实现验收，不能只检查初始页面。

## 交付与验收

- [ ] 需要改版的页面附用户选定图、状态说明与三项技能要求；已有澄清页面的复用或改造结论明确。
