# 通读候选更新与回读收益验证

对应想法004。用户于2026-11-15明确要求通读时更新或撤回已解决候选，只在需要核对原文时回读，并用原模型比较实际收益。本文件落实该授权，不扩大界面、数据范围或发布范围。

## 方案与边界

复用现有候选、来源摘录、容量打包和断点。新增候选稳定编号和阅读响应中的更新动作。后续批次优先携带相关候选与经原文验证的关键摘录，模型可更新问题及缺失细节，或直接保存有依据的修正结果。撤回旧解释也是解决：保留反例和当次事实，不另建撤回状态。已经解决的候选不进入额外核查；后文出现新证据仍可用同一编号重开。

例如合成聚会聊天：A说每次由自己安排，后文B指出上月由B安排，A确认并撤回每次的概括。预期在阅读后文时完成修正，成稿保留这次付出与疲累，不再调用核查去获取已明确提供的澄清。如果后来出现一个条件不明确的改期安排，可保留具体待核对事项，不能把泛泛的不确定都变成回读任务。

采用批次内更新，避免另加一轮模型来筛选候选；只改提示词而不改状态无法撤回旧队列，故同时增加最小响应协议。沿用已有模块，不引入检索服务、依赖或新的编排框架。

阅读响应增加可选 `candidateUpdates`：`revise` 用稳定id更新观察、支持来源、仍需核对的reason及摘录；`resolve` 用稳定id与完整finding保存修正、支持、反例、其他解释和限制。新候选保存reason与摘录，旧响应缺字段仍兼容。仅允许更新本批实际发出的编号；依据仅限当前原文和实际传入的已验证摘录，不因来源属于历史范围就直接放行。任务总候选、轮次、调用和用量上限不增加，恢复不清零。

## 重点审阅

候选被原文打包挤掉而无法更新；模型更新未显示的候选或引用未收到的旧来源；撤回后原错误解释仍进入报告；断点恢复重复调用或清预算；已解决事项被后来材料误当成永久结论。前四项由核心任务行为测试覆盖，第五项用重开回归与人工核对覆盖。

详细对照材料与通过标准在首次实际调用前写入独立试验记录；本文件不预先断言效果。

## 实际交付与限制
