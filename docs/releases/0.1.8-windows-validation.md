# Whomi 0.1.8 本地 Windows 验收

2026 年 11 月 1 日。从与 origin/main 一致的 `07fe5a8` 和已在本地验收的 0.1.7 工作区继续开发。测试使用隔离资料库、虚构聊天和本机模拟服务。此前已验收的服务商预置、模型配置、文稿、分栏、设计样稿和许可证一并保留。

## 先验证容量和旧任务

用 0.1.7 实际打包程序建了两项任务，然后用新桌面程序重开同一资料库。

| 原状态 | 新版结果 |
| --- | --- |
| 任务 1，共 14,639 条虚构短消息。首批在本机预检时超限，进度为 0，模拟服务收到 0 批原文 | 在 360 像素窗口继续，分 10 批发送原文。收到的原文编号精确等于 1 至 14,639，同一编号没有重发，沿原任务保存一份成稿。[窄窗完成](assets/0.1.8/capacity-14639.png) |

新版按完整请求核对字节预算，包含指令、数组分隔符与可带入的已知事件名。来源提取、事件合并、文稿撰写分别区分本机容量和服务端明确拒绝。旧批次按已保存范围复用，已拆开的长消息保留原有字符边界。检查还覆盖上下文容量 128,000、有效输入上限 119,808 的 14,639 条合成样本、2,000 条连续发言、旧归并节点、表情字符及同名不同身份。

## 安装包与跨版本结果

Windows x64 安装包位于本地 `release/0.1.8/Whomi Setup 0.1.8.exe`，大小为 178,438,145 字节。SHA-256 校验值为 `430A78B35987C159CA3D7666C8732C30F67FA75BBC72CE96592072100590B48E`。桌面程序文件版本为 `0.1.8.0`。打包档案中的 35 个构建文件逐字节匹配最终构建输出，另外核对了 4 份许可和声明。

用 0.1.7 和 0.1.8 的实际程序运行了 4 项打包版测试，均通过。两项分别走完宽窗、窄窗的首次对话与配置返回流程。一项核对上述两份断点。另一项核对升级前后的原会话、身份、模型、旧成稿与问答，升级后原加密凭据可用，重启仍保留配置，已完成提取的旧任务只补发一次汇总请求。

类型检查通过。前端 30 个文件共 292 项通过，后端 38 个文件共 473 项通过。开发构建完成 37 项桌面操作回归，另有 2 项跨版本用例只在提供旧版和新版可执行程序时运行，已包含在上面的打包版结果中。桌面回归覆盖 19 条引用整组高亮、两类会话管理及重启后拖序、同一事件跨分片只写一次、按关系投票与平票展示。

## 在本机复核

在仓库根目录运行类型检查、`npm test`、`npm run test:backend -- --maxWorkers=1` 和 `npm run desktop:build`。运行 `npm run test:desktop` 可检查开发构建。跨版本容量用例需同时提供两个版本的程序，使用 PowerShell 在仓库根目录执行以下命令。程序会创建独立的临时资料库和本机模拟服务。

```powershell
$env:WHOMI_OLD_EXECUTABLE = (Resolve-Path 'release/0.1.7/win-unpacked/Whomi.exe').Path
$env:WHOMI_PACKAGED_EXECUTABLE = (Resolve-Path 'release/0.1.8/win-unpacked/Whomi.exe').Path
$env:WHOMI_CAPACITY_STAGE = 'both'
node node_modules/@playwright/test/cli.js test tests/desktop/memory-capacity-upgrade.spec.mjs tests/desktop/upgrade.spec.mjs --workers=1
```
