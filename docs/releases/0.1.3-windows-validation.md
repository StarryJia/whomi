## 安装与升级

产物：`release/Whomi Setup 0.1.3.exe`，Windows x64，未签名的本地验收包，保留可选择安装位置的向导。先关闭 Whomi，再用原 Windows 账户运行新安装包，沿用原位置升级，无需先卸载。

程序标识 `local.whomi.desktop`、产品名 Whomi 和包名 whomi 均与 0.1.2 一致。默认用户数据目录不变，自定义目录指针仍放在原用户数据目录；加密密钥继续使用同一系统用户的凭据存储。例如旧版本保存了会话及一个模型密钥，新版本首次启动迁移模型配置后，原模型编号与密文保持不变，旧报告仍可查看。

安装配置显式设置 `deleteAppDataOnUninstall: false`。已核对本地 electron-builder 26.18.0 的安装脚本：普通升级使用 `--updated` 调用旧卸载器，替换安装文件，不删除用户数据目录。没有在用户的实际安装位置执行覆盖安装。

审查发现并修复了安装目录内保存数据的风险。设置现在拒绝把数据迁入安装根、其子目录或包含安装根的目录。例如 `D:\Apps\Whomi\data` 不能作为会话保存位置，独立的 `D:\Whomi-data` 可正常迁移。目标选择和迁移执行都会重新检查，避免升级清理安装目录时误删会话。

## 验收方式与边界

- 从现有 0.1.2 安装包提取真实程序负载，用受校验的系统临时目录创建虚构会话、本人身份、报告、对话和系统加密模型密钥；随后用新安装包中的程序打开同一目录。
- 比较会话、来源、成员、本人确认、消息、模型、模型历史版本、报告和对话九张表的摘要；通过本地合成模型服务确认旧密钥仍能解密并用于请求。
- 保存新消息处理规则与两个功能的模型选择后，再次启动新版，核对配置完整保留；另执行正式打包程序的设置全流程与运行恢复测试。
- 只操作隔离测试数据，不读取用户真实会话，不使用付费模型，不改写当前用户的安装注册表。真实安装器的文件替换策略依据已核对的打包脚本；进程升级兼容使用安装包内真实负载验证。
