# 吕布虚构数据与正式版实测

从吕布的视角，给貂蝉、董卓和高顺各导入一段虚构私聊。[人物设定](persona.md) 区分史料与文学假设，[首轮原文](conversations.md) 和 [第二轮补充原文](round-2/README.md) 保留了两轮全部对话。真实生成内容见 [正式版实测记录](results/2026-11-02.md)。

## 首轮输入

| 对方 | 独立事件 | 消息 | 用途 |
| --- | ---: | ---: | --- |
| [貂蝉](conversations/diaochan.chatlab.json) | 10 | 62 | 关系记忆；最后八句用于 AI 对话展示 |
| [董卓](conversations/dongzhuo.chatlab.json) | 8 | 48 | 权力与信任场景，补充另一段关系的证据 |
| [高顺](conversations/gaoshun.chatlab.json) | 9 | 54 | 合作、判断和安排场景，补充第三段关系的证据 |

三个文件都只包含两位说话人，本人均为吕布，共 164 条消息。ChatLab 是聊天记录交换格式；`platform: telegram` 仅是导入容器标记，不表示来自真实 Telegram 账号。人物标识和消息标识保持稳定，日期为架空排序日期。

`scenes.mjs` 保存手写原文及作者核对点；`build-fixtures.mjs` 生成三个导入文件、可读原文和带 SHA-256 文件校验值的 `manifest.json`。作者核对点与人格设定不进入导入文件，也不附加给模型。运行：

```sh
node docs/fixtures/lvbu/build-fixtures.mjs
```

首轮输入定为 `lvbu-v1`。独立事件数是作者构造的场景数，各维度的有效事件数见生成结果中的 `eventVotes`。

## 第二轮输入

在上述三段会话的基础上，分别导入 [高顺补充文件](round-2/gaoshun.chatlab.json) 和 [董卓补充文件](round-2/dongzhuo.chatlab.json)，再整理这两段会话。每个文件有六件新事。两轮合计 214 条消息，其中貂蝉 62 条、高顺 80 条、董卓 72 条。首轮三个导入文件可以独立复测。

## 正式版操作与验收

使用本地安装的 `D:\Chat\Whomi\Whomi.exe`。记忆与问答最初在 0.1.10 中生成，现已在 0.1.11 中核验并重新截图。记忆分析使用已配置的 Codex、GPT-6.1-Sol、高思考强度，首页引用问答使用同一模型、默认思考强度。

1. 依次导入三个文件，各选择吕布为本人。核对 62、48、54 条消息和每段的两位成员。
2. 每段分别整理成记忆。保存生成结果、事件引用、人格各维度及无法判断的原因。先完成背景记忆，再进行展示提问。
3. 查看个人总览，核查关系间的共同偏好与差异。单条语气、对方的话、同一事件反复出现，不应膨胀为多条独立的本人证据。
4. 在貂蝉会话中引用西门之约的八句原话，发送[使用指南中的问题](../../getting-started.md#试一次引用提问)。核对回答里的观察是否能在八句原话中找到依据，以及哪些解读仍需当事人确认。
5. 若只有空白或材料不足，先保存本轮结果，再针对缺失场景补充独立事件。不得为了得到指定四字母标签而重写输入。

核查例：貂蝉说“明日他问起来，还是我答”，应能识别她担心后续由自己承担；不能把这直接写成董卓已经威胁她。吕布答应等待，应和最初直接接人的冲动一起分析，不能仅凭这八句宣布人格发生永久改变。
