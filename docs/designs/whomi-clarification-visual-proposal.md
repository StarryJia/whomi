# 解惑视觉提案与会话界面调整

日期：2026-10-28。状态：会话菜单分组与示例内容调整已实现；用户确认 B 轻扇形修订稿并授权仅实现前端，解惑页面与开发预览已完成。所有图稿、人物、问题、选项及对话均为虚构示例。实现、验证与业务边界见[解惑前端实现记录](whomi-clarification-implementation.md)。

## 已完成的两项调整

- 会话标题、管理和导入置于同一个浅灰菜单容器，保持三个独立按钮，避免按钮嵌套。例：用户移动到会话行即可辨认两个工具属于会话；点击加号仍只进入文件选择，管理功能仍明确未开放。
- 保持项目讨论与朋友答辩主题，替换编号占位记录，增加回应、追问、纠正和生活细节。例：朋友说明只想找个人听试讲，对方承认翻到了旧版图，再约时间；Spark 摘要和引用范围同步覆盖这些来回，不能把一次提建议描述成始终准确理解他人。

本轮继续在用户已确认的 main 开发，实施前 fetch、pull 成功，HEAD 与 origin/main 均为 4427e57。上一轮个人总览成果保留为未提交改动，没有提交或推送。

## 解惑的已确认交互

页面由一个问题框、几张预置内容卡牌和底部自己回答输入框组成，继续服务于用户澄清具体材料里的疑问。卡牌与输入框是互斥作答路径，不将输入作为卡牌答案的补充。

### 最新修订

- 删除这些都不太贴近卡牌，当前示例保留三张实际选项。若均不符合，用户直接进入底部输入框。
- 输入提示改为以上都不符合，我有自己的想法…，不再写补充当时的想法。例：用户选择自己回答后，三张卡牌仍可阅读但不可选；切回卡牌时保留未提交草稿，不混入卡牌答案，也不自动提交。
- 原文入口改为回顾那段情景。例：用户需要重新理解朋友当时的处境，点击入口查看关联材料的上下文，再回到同一道题；这次改名不新增场景重建后台或新的证据来源。

用户明确选择点击卡牌立即提交，并提供撤回接口。例：用户选了主要想帮他赶完眼前的事，提交成功后看到该回答与撤回回答；发现误触，撤回成功后恢复原题及未回答状态，不自动换新题，不要求解释原因。

| 情况 | 建议的页面行为 |
|---|---|
| 初始问题 | 问题描述一段交流的背景与待澄清处，提供原文范围入口。例：说明朋友答辩前的压力、练习与改约，再询问用户当时更在意什么，而不是用一句话判断人格 |
| 点击卡牌 | 立即发起该选项的提交，显示真实处理中状态；阻止重复提交。悬停或聚焦不会提交 |
| 提交成功 | 明确显示已提交的回答与撤回回答，不显示画像已经更新；原问题保留，便于纠正误触 |
| 提交失败 | 留在同一道问题，保留自己回答草稿，允许重试该选项，不假装已经接收 |
| 撤回成功 | 同一道问题恢复未回答；自己回答草稿保留。撤回不是一道新题，不据此生成替换题 |
| 撤回处理中或失败 | 等待真实撤回回执。失败时保留已提交的回答，提供重试撤回，不能提前把界面清成未回答 |
| 选项均不贴近 | 直接进入底部自己回答，不额外提供一张以上都不符合卡牌 |
| 自己回答 | 进入此路径后卡牌不可选，输入是独立答案；点击改用卡牌回答可恢复选卡。切换保留草稿，不触发发送，不把草稿与卡牌答案合并 |
| 卡牌已提交 | 处理中阻止同时输入发送或连点提交；提交成功后，需撤回成功再切换为自己回答。撤回处理中仍保持已提交状态 |
| 同时触发 | 卡牌点击与输入框发送共用同题提交锁，同一道题只能产生一次有效提交 |
| 模型选择 | 只展示实际配置且可用的模型。模型列表、当前模型与选择事件通过接口传入；图稿的选择模型不代表已有模型服务 |
| 无问题、无模型、来源失效 | 分别保留诚实状态，不凑题、不伪造模型名或已发送结果；失效原文不可跳错位置 |

撤回接口建议撤销本题的回答及其参与后续处理的资格；这是待业务实现时确定的范围，不能仅靠前端按钮保证收回已经发出的模型请求。真实保存、请求取消和已处理结果的修正需要业务层支持，本轮不新增这些能力。前端已提供卡牌提交、自己回答发送与撤回的异步接口，在开发预览中明确模拟；没有适配器时不能宣称真实提交或撤回成功。后续模型回复不能作为新的独立证据。

未答题稳定保留、每天最多三道新题及没有疑问不刷新仍按主设计执行。跨日额度、时区和真实持久化继续待定。本提案不新增额度算法，也不以撤回重抽题。

## 首轮三个视觉方案，历史参考

| 方案 | 信息组织 | 场景与代价 |
|---|---|---|
| A 平铺牌列 | 上方问题框，四张直立牌面并排，底部输入 | 用户一次看清全部答案，长选项容易比较；牌感较克制 |
| B 轻扇形牌阵，推荐 | 问题在上，四张牌轻微展开，输入固定在阅读区域底部 | 最贴近用户提出的塔罗牌手感；卡牌只重叠空白边缘，较长内容和窄屏需展开为整齐网格 |
| C 左问右选 | 左侧问题，右侧两行卡牌，下方通栏输入 | 长问题可持续对照选项；分栏占用更多横向空间，窄屏顺序改为问题、卡牌、输入 |

首轮三稿已生成并人工查看，保存于本机 gstack 项目的 `designs/clarification-20261028/variant-A.png`、`variant-B.png`、`variant-C.png`。首轮图中的第四张卡和补充输入语义已被最新修订替代。当前修订在 `designs/clarification-20261028-r2/state-cards.png` 与 `state-own.png`，分别展示三张牌可选、自己回答时牌面不可选的状态。图稿中悬起的牌仅示意姿态，不是动画验收证据；正式组件需另行实测。

牌面正面直接显示内容。悬停采用轻微抬起与倾斜，焦点提供同等反馈；不翻转后才显示答案、不随机抽牌。触屏直接可选，减少动态效果时取消位移和旋转。底部输入栏不能遮住卡牌、错误提示或键盘焦点；中文输入法组合输入时按 Enter 不应发送。

## 现成组件核查与建议

本次只查官方仓库、文档和输入组件源码，没有安装新依赖，也没有证明与 Whomi 实际兼容。三个候选均不负责解惑问题、每日额度、回答撤回与材料判断。

| 候选 | 官方资料与本次核查 | Whomi 场景及剩余成本 |
|---|---|---|
| AI Elements | [仓库](https://github.com/vercel/ai-elements)、[Prompt Input](https://elements.ai-sdk.dev/components/prompt-input)，Apache-2.0。官方文档声明计划 2026 年 11 月末弃用并迁往 shadcn/ui；本次发布页可见 1.9.1 | 可组合输入与模型菜单，但引入 shadcn 和 Tailwind 4 的适配与迁移成本较高，不适合只为本页整体采用 |
| assistant-ui Composer | [组件文档](https://www.assistant-ui.com/docs/primitives/composer)、[仓库](https://github.com/assistant-ui/assistant-ui)，MIT。本次发布页可见 React 0.15.31，持续发布 | 无样式输入可沿用品牌，但需运行时上下文和额外依赖；本轮没有对话服务，整体接入偏重 |
| prompt-kit | [仓库](https://github.com/ibelick/prompt-kit)、[输入源码](https://raw.githubusercontent.com/ibelick/prompt-kit/main/components/prompt-kit/prompt-input.tsx)，MIT。本次核查声明版本 0.1.0、无 GitHub Release；该输入组件约 220 行，依赖 React 与本地文本框、提示、样式工具 | 受控输入、自增高文本区和操作栏结构可局部参考。用户选择自己回答时，底部留模型菜单和发送状态即可，无须迁入整套项目 |

推荐继续采用已有 React、普通样式表、Tooltip 和图标，参考 prompt-kit 的输入组织方式；本轮不新增依赖，不直接复制其源码。若以后复制源码，需保留相应许可声明。卡牌、原题保持、提交与撤回的状态和事件由 Whomi 实现，真实模型调用与存储单独确认。

没有影响该局部复用建议的关键兼容性疑点，当前不安装整套产品作验证。真实模型接入前，再以一个已配置模型、一题和一次可撤回回答验证数据流与失败恢复。实际用户规模本次未获可核实数字，不以星标或下载量替代。
