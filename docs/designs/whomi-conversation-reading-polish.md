## 已实现行为

| 事项 | 用户操作及结果 |
| --- | --- |
| 回答排版 | 发送固定示例问题后，回答显示两个标题、三条列表和两行数据表格；原始聊天中的符号仍按原文呈现。长代码和表格在局部横向滚动，不撑宽页面。 |
| 空间与历史 | 1280 × 800、侧栏240像素时，原文约395像素，AI内容约644像素；首次不显示历史列。主动打开历史后选另一条，再返回，原草稿、待发送引用与阅读位置恢复。 |
| 模型身份 | 甲生成后切乙，旧回答仍署名甲；甲改名、停用、重启后，旧回答及统计继续读取其生成时版本。历史版本缺失显示未知模型。 |
| 统计 | 示例输出100、总耗时10秒、首个输出等待9秒，摘要与主要详情都显示每秒100，端到端为每秒10；等待时间缺失时不冒充已知速度。桌面主项允许换行，360像素时逐行展示，数字与单位均完整显示。 |
| 复制 | 回答底部复制原始 Markdown，包含标题、列表和表格；写入成功才显示已复制。停止后的非空结果也可复制；写入失败允许重试且保留草稿。Windows剪贴板使用系统换行，验收按换行等价比较内容。 |

窄窗口沿用覆盖原文的兼容布局，关闭 AI 后返回原文。普通桌面保持并排。历史为 AI 区内临时浮层，选择、Escape、点击遮罩均可关闭，焦点回到历史按钮。

## 复用与必要适配

迁入 Cherry 固定提交 `f19aa72f969b782ed72f81be80976b237ae26605` 的通用 MarkdownCore 及依赖闭包，未迁入应用级全局状态。源码对照由独立评审逐文件核查；12个文件一致，核心文件仅将三个插件导入改为直接路径。

排版入口复用 Streamdown 2.5.0 的分块及 remend 1.3.0 的片段补全，将各区块交给 Cherry 原核心渲染。已复现直接重复渲染时最终快照可能仍显示旧文字，因此按内容刷新变化区块，保留未变化区块及局部横向位置；不自行编写 Markdown 解析器。结束时不切换整条回答的渲染树。流式跟随观察真实正文高度，用户向上阅读时暂停自动滚动。上游依赖仍带有 Mermaid 传递依赖，但未启用图表或高亮；来源及维护约束见 [UPSTREAM.md](../../src/vendor/cherry-markdown/UPSTREAM.md)。

模型身份复用已有 `ai_model_versions`，只返回编号、版本、显示名与调用标识四个字段，不增加快照表或返回凭据。历史没有服务商名称快照，不用当前服务商名称冒充旧身份。回答链接由主进程校验后在系统浏览器打开，仅接受无内嵌凭据的普通网页协议，继续拒绝文件和可执行协议；页面不自动加载回答中的远程图片。
