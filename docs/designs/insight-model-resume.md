# 洞察更换模型后接续 · 方案第 1 版

2026-11-27，维护者确认在 PR #54 的 codex/issue-49-evaluation-design 分支实现本方案，并要求验证后提供 Windows 安装包。当前状态：待维护者安装验收。

## 范围与复用

复用 Pi 1.4.0 的模型切换、历史消息转换、会话存储和上下文压缩，以及 Whomi 的阅读断点、来源引用和按服务商分组的模型选择。新增任务恢复参数、模型切换记录与逐次请求的模型归属；保留普通重试入口。

失败、暂停或中断的任务可展开「更换模型并继续」，选择已配置服务商的模型及支持的思考强度，提交后接续同一任务。取消时保留原任务；选中模型不可用时提示重新选择，保留原断点。例如洞察提交分析 5,762／14,771 条后余额耗尽，用户选择另一家服务商，继续处理剩余材料和成稿。

跨服务商沿用已保存的阅读内容、摘要和原文引用。Pi 转换协议消息并移除不适用于目标模型的签名推理。新模型容量变化时重新计算请求预算，必要时整理历史上下文。执行中先暂停再切换；不自动选择服务商。

报告阅读页和已完成报告列表移除生成模型字段；任务操作区保留选模信息，后台保留切换记录和各次请求归属。

错误分类优先检查具体供应商错误代码。余额、消费上限与明确的速率限制分别提示操作；没有具体证据的 429 或通用限额错误显示请求受限、原因未确认。错误信息不回显原始请求内容和密钥。

## 验收场景

- 合成任务已读部分消息后额度耗尽：取消选模后任务和进度不变；更换服务商与协议后沿用原编号完成报告，原文引用可打开。
- 目标模型不可用或设置发生变化：切换失败时保留原断点，可再次选择；完成后重启仍保留报告。
- 目标模型上下文更小：新请求遵守其容量，已读覆盖和累计用量保留；此前用量继续归属原模型。
- 未知 429 不误报请求过快；具体额度代码优先于通用 rate_limit_error；流内错误和普通错误一致分类。
- 宽窗口和 480 像素窄窗口均可选择、取消、接续；已完成列表及报告正文没有生成模型字段。

## 验证与交付

本轮使用合成数据和本机模拟服务，未调用真实收费接口。合成任务在 1／8 条时额度耗尽，取消选择、无效目标与重启都保留原任务。由 OpenAI Responses 切换至另一服务商的 Chat Completions 后，仍以原编号完成 8／8 条并打开引用原文。

前端全量 703 项通过；后端全量 996 项首次 991 项通过、5 项失败，原因是旧版本迁移样本保留了本轮新增列。修正样本后对应 50 项全部通过，真实版本 16→17 迁移专测通过。最终类型检查与桌面构建通过。

补测期间发现并修复两处容量边界：思考强度改变时重算预算；更换模型后重新估算历史内容，避免使用原模型用量回执。跨协议、同名模型、小窗口拒绝后原断点恢复等 44 项通过。首次协议测试的地址断言遗漏查询参数，修正断言后 108 项通过；所有首次与复测记录均保留。

首次开发桌面流程通过。包内程序首次测试在异步切换接受前读取原模型的失败状态而失败，随后保存的现场已经是新模型和 running 状态。修正脚本等待条件后，同一安装包完整流程通过；产品代码未因此修改。
