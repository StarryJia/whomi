# Whomi 设置界面设计

设计日期：2026-10-28。2026-10-31 已按用户确认接入正式设置、模型服务、消息处理和数据保存目录；当前行为与验证见[正式接入记录](whomi-settings-implementation.md)。下方第 1～11 节保留设计阶段记录，其中待确认与仅演示的描述不代表当前正式入口。

本轮在用户确认的 `main` 分支开展，保留已有未提交改动；已获取远端记录并完成拉取，开始时 `main` 与 `origin/main` 提交差异为零。本文件是[页面设计第 06 章](whomi-page-design-v0.1.md#页面-06设置与模型配置页)的补充，不新增全局一级页面。

## 1. 设计简报

按 impeccable 的 shape 流程整理，界面模式为 Operate，即让用户完成配置任务的应用界面。

- **用户与任务**：希望用自己的聊天材料理解自己的个人用户，从侧栏底部设置进入，配置模型服务、整理发送给模型的材料、查看项目与数据使用信息。
- **完成标准**：用户能辨认当前服务商、修改字段、选择明确归属的模型，也能区分开关状态、规则选择与真实处理结果。例如勾选邮箱和手机号后，应读到已选 2 项；不能显示聊天已脱敏。
- **视觉依据**：延续 [PRODUCT.md](../../PRODUCT.md)、[DESIGN.md](../../DESIGN.md)和现有页面的原始 Logo、系统字体、白色与浅冷灰表面、橙色强调、细分隔线及可见焦点。原则原文：让复杂的功能看起来简单，让简单的操作感到愉悦，让整个页面既有设计感，又不需要用户思考如何使用。
- **组织方式**：设置内部只含模型服务、消息处理、关于whomi。先比较整体结构及模型服务布局；选定后将同一语言应用到其余分类，不为三个分类分别选择品牌风格。
- **交付边界**：设计文档、静态候选及选定后必要的独立交互预览。正式业务流程、后端、真实连接、配置持久化和消息处理算法均不修改。
- **证据边界**：实际页面与源码可说明已有界面；静态候选只能说明视觉。独立交互预览位于 `previews/settings/index.html`，所有配置仅在内存中演示；具体检查结果见末尾记录，不代表真实连接或处理能力。
- **开放决定**：A 布局已选定；默认状态、保存方式、数值范围及恢复默认范围等待用户确认，设计者不代填为已确认结论。

## 3. 整体结构与视觉候选

三案共享相同字体、品牌、色彩、表单内容和任务范围，只比较设置工作区的组织方式。A 已由用户明确选定；B、C 保留为历史比较。修订后的三个分类共用 A 的导航及视觉语言。

| 候选 | 结构与使用场景 | 取舍 |
|---|---|---|
| A：专注设置 | 设置分类侧栏＋服务商列表＋配置详情，顶部提供返回。例如用户连续配置两家服务商时，分类与服务商位置始终清晰 | 配置任务集中；进入设置时业务侧栏暂由设置导航替代 |
| B：顶部分类 | 顶部模型服务／消息处理／关于whomi，下方服务商列表＋详情。例如用户在模型和消息处理间切换，横向定位三个分类 | 给详情更多宽度；分类与服务商处于不同导航方向 |
| C：保留业务侧栏 | 保留客户端侧栏，主区顶部分类，下方列表＋详情。例如用户配置后希望随时回到原会话 | 连续性更强；窄窗下多栏压缩最明显 |

视觉方案见[独立比较页](previews/whomi-settings-concepts.html)，原图与生成提示见[附件说明](assets/settings/README.md)。比较页保留首轮静态候选；[A 方案交互预览](previews/settings/index.html)承接用户选定后的修订，不能以历史候选替代当前版本。

导航提案：从底部设置进入后保留原页面、选中会话和阅读位置；返回恢复原页面，并将焦点归还设置入口。若原入口已不存在，焦点移至对应页面标题。例如在某段原文中进入设置，返回后仍是这段原文，不跳回 Hello。该返回细节尚待确认。

分类切换只改变设置内容。字段发生修改时就近显示修改状态；采用立即生效、显式保存或离开时提示尚待确认，不先绘制假装可用的保存成功回执。需要放弃修改提示时，应明确影响范围并提供继续编辑；不得用普通弹窗关闭代替真实保存方案。

## 4. 模型服务

### 4.1 服务商列表与连接配置

服务商列表先提供搜索，再显示名称、启停状态及模型数量，底部或列表工具区提供添加自定义服务商。启停与检测结果为两个独立信息，不用一个彩色圆点同时表示二者。

| 交互 | 内容与反馈 | 虚构示例及验收 |
|---|---|---|
| 搜索与选择 | 搜索服务商名称；选中项突出，详情标题重复完整名称 | 输入示例云，选择示例云服务，右侧标题和字段属于同一服务商；清空搜索可恢复列表 |
| 添加自定义服务商 | 名称、连接协议、接口地址和按服务类型需要的密钥；协议需标明具体兼容对象 | 填写示例服务、示例协议及 `https://models.example.invalid/v1`；不触发请求，名称为空时在字段下提示填写 |
| 启用与停用 | 控件有名称与状态文字；停用后保留配置的提案待确认 | 停用示例服务只改变演示启停状态，不显示连接失败，也不移除字段 |
| 本地与云服务 | 按选定服务类型展示所需字段，不强制所有服务填写密钥；协议不能靠名称猜测 | 选择示例本地服务后显示本机地址字段，密钥仅在该服务需要认证时要求填写 |
| 密钥显示 | 默认遮蔽，主动显示／隐藏，按钮有可读名称，禁止在提示中回显密钥 | 只用 `DEMO_KEY_NOT_VALID`，显示后再隐藏可检查视觉；不使用真实密钥 |
| 连接检测 | 未检测、检测中、成功、失败，结果关联当前字段版本 | 点击演示检测显示检测中与演示结果；失败提供检查地址与密钥的操作；修改地址后旧结果不继续代表新地址 |

协议选项的首批支持范围仍待确认，不从 Cherry 的提供商数量推导 Whomi 支持范围。订阅登录等特殊认证仅记录为开放问题，本轮不绘制登录流程。

设计用文案：接口地址、密钥、显示密钥、隐藏密钥、检测连接、同步模型、手动添加。接口地址无协议时可提示请输入以 http:// 或 https:// 开头的地址；格式校验仅用于界面输入，不等于地址可访问。

演示检测必须标为演示；例如检测成功 · 演示，不能直接显示连接成功。检测中保留上下文，避免重复触发；切换服务商不能把上一家的检测结果显示到下一家。

### 4.2 模型列表与弹窗

已有解惑模型选择器通过 `ClarificationModel` 的 `id`、`label`、`available` 接收模型，当前预览名称为示例模型 A、示例模型 B。设置稿沿用这些名称，不声称已完成与设置的数据对接。

| 操作 | 设计与边界 | 虚构示例及验收 |
|---|---|---|
| 同步模型 | 打开当前服务商的模型选择弹窗，显示演示来源；真实能力留待后续适配 | 示例云同步出示例模型 A、B，只是预设清单，不发送请求 |
| 搜索与多选 | 标题带服务商名；搜索下列出复选框；已添加模型有独立标识，不能重复添加 | 勾选 A 后搜索 B，再勾选 B，已选显示 2，不因筛选丢失 A |
| 全选 | 文案明确全选当前结果，反映全选、部分、未选；搜索改变后重新计算当前结果状态 | 搜索仅匹配 B 时全选只改变 B；A 的已有选择保持 |
| 添加所选 | 显示数量，零选不可执行；底部动作与结果列表分别保持可见和可滚动 | 添加所选模型 2 后，示例列表增加 A、B，不宣称服务商已经返回真实模型 |
| 手动添加与编辑 | 输入模型标识和展示名；错误靠近字段；编辑保留服务商归属 | 在示例云手动添加示例模型 A，重复标识时提示该服务商下已存在此模型 |
| 移除 | 指明移除的是当前服务商的模型条目，后续对已选模型的影响待确认 | 从示例云移除 A，不能连带移除示例本地服务的同名 A |
| 关闭弹窗 | 取消或 Escape 关闭并归还焦点；弹窗未确认选择不写入模型列表 | 勾选 A 后取消，详情列表不新增 A；再次打开的临时选择恢复策略另行确认 |

同名模型显示示例模型 A · 示例云、示例模型 A · 示例本地服务。后续建议由服务商标识与模型标识共同确定身份，即 `providerId + modelId`；这是实现依赖提案，不是本轮已完成的数据结构迁移。

启停、未检测和模型是否可用不混为一谈。现有选择器只展示可用模型；未检测是否允许选择、停用后已选模型如何回退需单独确认，不静默换成另一模型。

## 5. 消息处理

页首说明：整理发送给模型的材料，原始记录保持不变。以下只定义控件，不定义处理次序、识别规则或算法。

| 设置 | 建议用户说明与渐进展开 | 虚构场景及验收 |
|---|---|---|
| 数据清洗 | 整理分享卡片中的链接、小程序等内容。必要帮助说明 XML 是一种结构化文本格式，首屏不要求理解它 | 用户开启后只看到开关变化；不展示某条聊天已经被转换，也不改变原始卡片 |
| 合并连续发言 | 合并同一说话者在短时间内连续发送的消息；开启后出现合并时间窗口、秒数输入、减少与增加按钮 | 开启后输入演示值 180，可通过按钮调整；180 不是已确认默认值，最小值、最大值和步长待定 |
| 智能去噪 | 过滤可能缺少有效内容的语气词、纯表情或系统占位消息，可能减少分析材料 | 用户考虑保留否定、语气或表情时可关闭；不承诺过滤无损或总能正确判断 |
| 昵称匿名化 | 在交给模型的材料中用 U1、U2 等编号代替昵称；原始聊天仍显示原昵称 | 开启后只更新控件状态；原文显示和说话者、证据的对应关系不能因此改变 |
| 数据脱敏 | 替换所选类型的敏感信息；开启后显示可展开的规则组与已选数量 | 仅选邮箱和手机号显示已选 2/10；不显示真实材料已经匿名化或脱敏 |

合并时间输入允许手动输入与增减，标签始终可见；输入空值或非数字时给就近提示，不擅自改回 180。具体有效范围确认后再定义越界提示与按钮禁用条件。

### 5.1 脱敏规则组

本轮规则共 5 组、10 项。组选择使用复选框，展开按钮独立于组选择；组标题显示已选数量，折叠后仍能读到选择摘要。

| 组 | 单项 | 虚构占位内容 |
|---|---|---|
| 密码与访问凭据 | 已知前缀的接口密钥；Bearer Token 授权令牌 | `[演示接口密钥]`、`[演示授权令牌]`，不提供可用凭据 |
| 通用联系方式 | 电子邮箱 | `person@example.invalid` |
| 通用金融信息 | 信用卡号 | `[演示信用卡号]` |
| 通用网络信息 | IPv4 地址，即互联网协议第四版地址；网址 | `192.0.2.10`、`https://example.invalid` |
| 中国大陆 | 手机号；身份证号；银行卡号；座机号 | `[演示手机号]`、`[演示身份证号]`、`[演示银行卡号]`、`[演示座机号]` |

父复选框由子项计算：零项为空、部分为横线、全部为勾选，并同时提供已选数量。提案：部分状态点击组复选框后全选该组；再次点击取消全组。例如中国大陆只选手机号时显示 1/4 和部分选中，展开不改变选择。

数据脱敏总开关只控制功能启停，不能显示部分选中。提案：关闭时保留规则选择并收起，重新开启可恢复；这一保留策略待确认。折叠组不会取消子项。

恢复默认放在规则区域，与全页配置操作分开；默认集合和影响范围尚未确认。后续如需确认弹窗，应明确恢复哪些内容。例如仅恢复规则时不能连带修改合并时间或模型配置；此例说明应有的范围表达，不表示已确认恢复仅影响规则。

### 5.2 Whomi 特有边界

- 否定、语气、表情可能影响人格理解；例如虚构消息我不是不在乎与一个表情不能因篇幅短就被界面宣称为无意义内容。
- 清洗、合并、脱敏后的材料仍需关联原始消息；例如合并三条消息后，回查应定位这三条原文及上下文，不能只给一条改写文本。关联设计依赖后续消息标识与来源范围能力。
- 脱敏不能保证识别全部敏感信息，也不表示云服务商完全收不到私人内容；用户仍应确认发送范围。昵称编号也不能消除聊天内容中的所有身份线索。
- 本轮不编写正则表达式、消息转换、匿名化、脱敏或去噪程序，不制作暗示算法已经完成的前后对比结果。

## 8. 针对性设计规则来源

使用 ui-ux-pro-max 的局部检索，没有生成或覆盖全局设计系统。命令格式为 `python D:/CodexData/skills/ui-ux-pro-max/scripts/search.py 查询 --domain ux -n 3`；React 相关检索使用 `--stack react`。

| 查询 | 核验结果及采用范围 |
|---|---|
| `settings navigation back` | 命中可预测返回、键盘导航；返回条目标为移动端，只采用可预测返回原则，不照抄其路由代码 |
| `form labels error validation` | 命中可见关联标签、行内错误、可聚焦错误摘要；适用于本轮表单 |
| `modal keyboard focus trap`，重试 `dialog focus` | 仅可靠命中焦点可见和不被遮挡，未覆盖完整弹窗模式；补充官方依据 |
| `form dialog focus state --stack react` | 命中弹窗焦点圈定与关闭归还；示例不是完整弹窗实现，不能据此声称已验证 |
| `checkbox mixed group toggle`，重试 `checkbox indeterminate` | 两次均为 0 命中；不冒称技能库提供三态复选框规则，改用官方模式 |
| `narrow overflow long text scroll`；`scroll container focus` | 采用文字重排、长标识换行；滚动检索未覆盖弹窗细节，补充官方模式 |

补充依据：[W3C 模态弹窗模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)、[W3C 复选框模式](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox/)、[W3C 开关模式](https://www.w3.org/WAI/ARIA/apg/patterns/switch/)。W3C 指万维网联盟。混合复选框对应 `aria-checked=mixed`，开关只用双态；如采用原生复选框应正确设置其部分选中属性。

舍弃检索中的蓝色焦点示例、正数焦点排序、强制平滑滚动和用横向裁切掩盖溢出的建议；保留 Whomi 已有字体、颜色、组件及减少动态效果约束。

## 10. 首轮 critique 与比较页验证

方法：两个独立评审代理，A 为 `design_critique_a`，B 为 `design_critique_b`；前者审查三张概念图与品牌、产品上下文，后者扫描比较页并检查浏览器。该评审发生在用户选择前；用户随后明确选择 A，评审的 B 建议保留为历史意见，不替代用户选择。

A 提案适合同时查看分类和服务商；独立设计评审更推荐 B，理由是三个分类横向放置即可辨认，长地址与模型名称能获得更多宽度。C 的客户端连续性有价值，但多层导航占用最多空间。比较页保留这项分歧，让用户直接比较。

| 对 B 可见设计的启发式 | 分数／4 | 限制 |
|---|---|---|
| 系统状态可见 | 2 | 已启用与未检测还需靠近说明 |
| 用户语言 | 3 | 连接协议需简短说明 |
| 用户控制 | 2 | 保存与离开行为待确认 |
| 一致性 | 3 | 蓝色图标偏离既定语法 |
| 错误预防 | 2 | 未展示输入错误和移除边界 |
| 识别优于记忆 | 3 | 服务商与模型归属同时可见 |
| 使用效率 | 不适用 | 静态图不能验证 |
| 简洁与美感 | 3 | 区域明确，容器可继续收敛 |

| 帮助与说明 | 2 | 材料去向说明需提前 |

合计 20/32，仅评价 B 的可见设计，不是成品可用性评分。认知负担：A、B 较低，C 较高；判断依据是导航层级与配置先后是否清楚，不是机械累加屏幕中的全部按钮。

主要发现与修订要求：

1. **优先级 1：状态关系**。开启服务不等于可用；选定后的预览将检测状态放在服务标题附近。例如用户能同时读到已启用和未检测，而不把橙色开关理解为验证成功。
2. **优先级 1、用户待定：修改后离开**。保存方式未确认，不能凭候选默认自动保存。独立预览只保留内存，未来的正式保存策略需单独决定。
3. **优先级 2：材料去向**。云服务说明应出现在配置区上方，不只放在模型列表底部，让用户未滚动时就看见。
4. **优先级 2：视觉一致性**。选定后使用原始 Logo 与既有图标，去掉蓝色强调、过粗选中线及未确认的导航；候选图保留作比较依据，不作规范。
5. **优先级 2：空间与长内容**。A、C 需验证收窄后的顺序呈现；静态候选不能证明设置表单适配。

首次配置用户可能误解启用与检测，键盘用户需要图标可读名称、焦点和弹窗归还，高频用户需要搜索不丢选择。紧张点是填写密钥、判断材料去向和离开修改后的表单，优先完善这些位置。

比较页已增加启用与检测的区分、保存方式待确认、独立评审的 B 推荐理由和定稿修订说明。浏览器检查范围是比较页：1280 × 720 正常加载三张图；360 × 800 单列重排，文档宽 345 像素、不超过视口 360 像素。窄图中的表单细字需打开大图查看，不声称图片中的设置已实现响应式布局。
