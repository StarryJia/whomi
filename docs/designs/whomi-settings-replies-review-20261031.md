## 用户任务与采用方案

本页属于操作界面：用户配置服务商、选择模型或调整发送材料，返回会话继续阅读。沿用既有字体、白色表面、冷灰分隔及橙色操作色，不更换品牌或新增组件库。用户已确认单一协议直接显示、移除常驻未保存提示、模型目录在当前服务商模型区展开，并允许调整既有弹窗测试。

采用已有设置组件；复用现有模型同步、保存、失败重试、原文分页定位和返回机制；自行补齐 SIWX 引用字段与重复导入修复。模型目录展开时替代已添加模型列表，完成或收起后恢复列表，避免重复展示。连接配置保留在同一详情区，可通过滚动查看；编辑连接会收起旧目录，保存后才能重新同步。

没有引入 Cherry Studio 的运行代码。用户提供的 Cherry 截图用于确定模型区的信息组织；没有迁入其额外服务商、协议、图标库或功能。

## 发现与已完成修改

| 发现 | 根因与修改 | 实际验收场景 |
|---|---|---|
| 中：合并秒数的直角橙红框像输入错误 | 有效的 60 通过校验，框来自全局焦点样式。焦点改为整组数字控件的中性圆角边界，保留键盘可见反馈。 | 点击 60 不出现直角红框；输入 601 显示真实错误，改为 61 后保存。 |
| 中：消息处理说明与常驻保存备注增加噪声 | 页首改为说明发送前整理与隐私处理；移除空闲保存文案，保存中保留辅助技术可读状态，失败与重试仍可见。 | 用户只看到当前规则；保存失败仍能重试，不以精简文案移除必要反馈。 |
| 高：SIWX 引用只能阅读，不能跳转 | 旧解析忽略 rawContent 中 refermsg 的 svrid，并漏读 quote.displayname 与 quote.ts。新解析保留字符串编号，按会话内可靠编号解析目标。 | 虚构的第 700 条引用第 1 条；点击后加载已卸载的原文页，原消息进入阅读区，可返回引用位置，草稿不变。 |
| 中：单一协议仍伪装成选择框 | 当前只有一种协议，改为带标签的静态值。 | 添加服务商时直接读到 OpenAI Chat Completions 兼容，不再打开只有一个选项的原生菜单。 |
| 中：服务商未保存状态常驻 | 由保存按钮启停表达有无修改，保存回执供辅助技术读取；保留离开时的保存、放弃和继续编辑。 | 改名后保存按钮启用，页面无备注式未保存提示；直接离开仍可选择继续编辑。 |
| 中：同步模型遮挡整个配置 | 复用原组件改为模型区内联区域，保留搜索、多选、参数、错误恢复及部分保存后的剩余重试。 | 同步失败原地重试；收起未添加的选择不会保存模型；成功后同一区域显示已添加列表。 |
| 中：桌面图标视觉尺寸偏小 | 512 像素原图的实心主体仅约 388 像素宽。固定透明源图后，按主体边界等比生成图标，主体宽增为 486 像素。 | 48 像素槽位内的图形从约 36 像素增至约 46 像素；原始品牌资产不修改。 |

合并连续发言保留：同一人相邻文字消息的间隔不超过指定秒数时，按换行合并发送，并保留全部来源编号。例如虚构消息周六有空吗与十秒后的同一人消息一起练习，交给模型时合为两行，原记录仍是两条。参数约束是相邻消息间隔，不是整段发言的总时长。没有另行改变算法与默认值。

## 引用兼容与隐私边界

对用户授权的 SIWX 导出进行了本地结构检查，共 14715 条消息、408 条引用。修复后的解析对 408 条均保留了同文件内存在的目标编号、引用姓名与时间。检查只输出汇总数量，没有输出聊天正文、复制私人记录进仓库或向模型发送聊天。

已有记录需在修订版本中重新导入原文件一次，选择原会话作为目标；系统只为原消息和摘录相符的未解析引用补全关联，不重复添加消息，不改写原文或覆盖已解析关系。虚构回归验证再次导入后消息数仍为 700。缺少可靠编号、目标未导入或编号格式无效时继续保留静态摘录，不凭相同正文猜测目标。

格式依据：用户提供的实际文件结构，以及 [SIWX 引用解析源码](https://github.com/ImUpXuu/SIWX/blob/main/siwx/api_chat.py)；本轮只参考字段含义，未复制其运行实现。Windows 图标包含 16、20、24、32、40、48、64、96、128、256 像素图层，覆盖[微软文档要求的基础尺寸](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icon-construction)。

## 设计判断与后续复用

本轮限定范围发现 7 项问题，均已修改并验证。最值得直接改善的是单一协议去掉选择、常驻备注清理、组合输入焦点统一；这些都已完成。操作流程的主观可用性从 50/100 提升到 80/100，改善来源是明确可用操作、引用可回查、错误可恢复；该分数不是用户测量。

限定范围的设计评分 B → A，模板化视觉评分 A → A。交互状态 C → A，内容质量 B → A，间距与布局 B → A，其余视觉维度沿用既有约定；响应速度只观察即时反馈，没有性能基准测试，不将此评分推广到整个应用。机械检查无可比基线，只报告最终零条发现，不虚构数量差值。

Whomi 已有 DESIGN.md，问题是具体控件约束与验收没有完全落地。后续宜用 impeccable 的 document、extract 固化既有控件与样式，再用 design-review 验收正常、取消、失败和窄窗口；需要重新探索整套视觉方向时才使用 design-consultation。本轮已补充设置控件与反馈约束，没有宣称全应用组件库已完成。
