# Codex 剩余额度：方案 C

2026-11-02 已实现。用户选择紧凑列表，并明确选择主动连接本机 Codex、标明账号及工作区的独立额度来源。没有替换 Whomi 的 ChatGPT 登录或推理连接，没有生成安装包。

## 使用流程与状态

设置 → 模型服务 → OpenAI Codex，在 Whomi 已连接时点击「连接本机 Codex 用量」。同一区域显示来源邮箱、工作区、更新时间、实际返回的额度周期、剩余百分比和重置时间；「本机使用记录」默认折叠。邮箱仅展示，不用于把两个应用的授权关联起来。

| 场景 | 实际行为与验收示例 |
|---|---|
| 首次打开 | 未连接额度来源时不读取 Codex 登录文件，也不显示虚构百分比。点击连接才发起请求。 |
| 单周期与双周期 | 示例响应只有 604800 秒、已用 38%，显示每周剩余 62%；另有 18000 秒窗口才增加五小时一行。不按 Plus、Pro 名称硬编码。 |
| 刷新 | 保留旧值和绝对更新时间，禁用重复刷新；成功后更新数字，进度条平滑过渡。 |
| 网络失败 | 保留旧值，标明当前显示上次结果并提供重试。首次失败不显示百分比。 |
| 账号或工作区变化 | 每次请求前后核对来源身份。示例：同一邮箱从个人工作区切到团队工作区，旧数字清除，需要重新连接，也可直接断开。 |
| 取消与退出 | 连接期间可以取消；迟到响应不能恢复绑定。断开来源不退出 Codex。退出 Whomi 当前账号会断开其额度来源。 |
| 零额度和缺失数据 | 服务端已用 100% 才显示剩余 0%；缺失周期不补零，缺失重置时间显示未提供，空周期显示重试指引。 |
| 键盘与窄窗 | 状态替换时把仍属于当前操作的焦点移到新按钮，不抢走已经移开的焦点；提供读屏状态。360 像素下标签与百分比同排，进度条独占下一行，工作区可换行。 |

## 采用与复用

- 采用 Codex 官方源码所使用的固定只读地址 `https://chatgpt.com/backend-api/wham/usage`。复用其访问令牌与工作区请求头约定，不启动子进程或复制凭据到临时目录。
- 复用 Whomi 的设置进程通信、加密存储、账号状态核对、主题与按钮。`codex-quota.ts` 集中负责来源身份、绑定、并发合并、超时、响应校验和取消；界面仅接收额度与来源信息，不接收凭据。
- 自行实现方案 C 的呈现和状态交接。没有增加通用多服务商额度框架，也没有从本机词元数推算百分比。
- 本机额度来源按登录文件路径、用户标识和工作区生成指纹，并与 Whomi 授权账号关联保存。只保存加密的绑定标识，不保存 Codex 访问令牌或刷新令牌。

原有调用是设置页读取本机使用记录；新增额度调用独立进入 `codex-quota.ts`。若删除该模块，文件读取、身份核对、网络限制与取消处理会散回设置逻辑，因而集中维护具有实际作用。术语见 [GLOSSARY.md](../../GLOSSARY.md)。

## 来源与边界

读取 `$CODEX_HOME/auth.json`；未设置环境变量时读取用户主目录下 `.codex/auth.json`。仅支持普通 ChatGPT 登录文件；系统凭据存储、外部认证、密钥登录和政府云账户不在本次接入范围。访问凭据过期或被拒绝时，提示在 Codex 重新登录后重试；Whomi 不轮换或改写 Codex 凭据。文件路径可在来源文字的提示中查看。

该地址来自官方 Codex 实现，并非稳定公开的第三方用量接口承诺。查询设 15 秒超时、128 KiB 响应上限并禁止重定向；错误不转发服务端原文或凭据。将来地址或权限发生变化时，界面仍提供官方管理用量入口。

Whomi 现有使用 ChatGPT 登录的授权只面向 `https://api.openai.com/v1`，不能用它的本地账号散列充当 Codex 工作区。官方还允许按应用设置限制，因此本机 Codex 的剩余额度不保证 Whomi 的同名账号一定可用。
