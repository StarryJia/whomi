## 用户场景与当前行为

用户打开 Whomi 时，可能不知道 Hello 可以点击。现在有两条可发现的路径：

| 操作 | 可观察结果 |
|---|---|
| 选择侧栏个人总览 | 菜单位于分析上方，直接进入总览并标记当前位置；窄屏关闭导航面板，焦点移到总览标题 |
| 鼠标移入封面主区 | 遮罩在约 500 毫秒内变为半透明，下方出现模糊的同一份总览；不会自动进入，也不会触发分析 |
| 鼠标移出主区 | 遮罩恢复不透明；侧栏仍可独立操作 |
| 点击 Hello 或主区空白处 | 遮罩在约 600 毫秒内消失，模糊逐渐清除，之后进入总览并聚焦标题 |
| 用 Tab 聚焦封面，再按 Enter 或空格 | Hello 显示焦点框，主动激活后进入；仅聚焦不会透视总览 |
| 触屏点击封面 | 直接执行进入过渡，不要求先悬停；减少动态效果时直接切换 |
| 动画中点击品牌或切换其他菜单 | 取消原进入回调，后续不会意外切回总览 |

按用户最新修订，封面仅显示 Hello，不附带文字提示或箭头。点击主区任意位置仍可进入；侧栏、文件选择和会话正文保留各自操作。

品牌返回仍恢复 Hello，不重播已确认的启动动画。启动与刷新不恢复上次总览；原品牌开场的素材、时间轴与交互未修改。

## 复用与边界

复用现有 `PersonalOverview`、导航状态、图标与设计变量，新增 `HelloCover` 组织遮罩和进入过程；使用原生按钮与样式过渡，没有新增依赖。

- 封面首次悬停前不挂载总览预览；悬停后复用当前可用数据。正式入口没有真实分析数据时，透出的也是空状态，不填入示例。
- 预览始终不可操作，并通过 `inert` 与 `aria-hidden` 排除键盘和辅助技术访问。离开悬停后恢复遮挡；返回 Hello 会卸载先前的正文与预览，后续悬停可再次挂载预览。
- 预览与正式总览依次挂载，反馈状态仍由已有应用级接口管理。不生成数据，不保存视图，不接入模型或持久化服务。
- 完成动画才转移焦点；过渡事件缺失时有结束回调，卸载时清理。重复点击只执行一次进入，减少动态效果偏好改变时也可结束过渡。
- 强制颜色模式保持实色遮罩，仍可点击或键盘进入；该样式路径尚未在系统设置中实测。

例如，用户在开发预览中看到全部未知的类型，悬停和进入后都保持 `????`；封面不会因需要背景而编造人格结果。开发预览顶部仍明确标注虚构示例。
