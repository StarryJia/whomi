# 会话与模型交互补正

2026-10-31，在用户已确认的 main 分支继续，基线为 1a231bc。九项修改按用户提供的截图和操作要求实施，测试使用合成记录、隔离数据库与本机模型服务，不使用真实聊天和密钥。

## 使用场景与行为

| 用户操作 | 当前行为 | 验收点 |
| --- | --- | --- |
| 选中两条示例消息后取消 | 已选数量旁提供取消选择，清除全部高亮与待发送引用，仍可重新选择 | 清空后选择第一条，数量和引用重新计算 |
| 在窄窗关闭 AI 侧窗 | 标题区预留 Windows 系统控制高度，关闭按钮位于其下 | 1280、960、360 像素窗口核对实际位置与鼠标命中 |
| 为同一聊天建立两条 AI 对话 | 原文右上角打开侧窗，历史列表位于左侧；新建和切换使用各自的消息、运行断点与草稿 | 第一条草稿在切回后保留，第二条请求不携带第一条历史，重启后两条仍在 |
| 从左侧选中原始会话 | 只用背景高亮标识当前项，保留键盘焦点样式 | 没有额外红色边条 |
| 查看缺少部分用量的回答 | 沿用 Cherry 统计字段，已知值照常显示，未知值留横线，不追加统计不完整或单位解释 | 输出已知、输入未知时不编造输入零值 |
| 配置示例文本模型服务 | 四种自定义文本协议可选，协议贯通目录、检测、实际请求和用量统计 | 原生请求路径、认证、分页、错误、取消与旧模型版本分别验证 |
| 批量添加目录模型 | 全选只勾选当前列表，取消个别项后点击添加才保存；取消放弃尚未提交的选择 | 全选与取消不调用保存，部分失败保留成功项和待重试项 |
| 筛选服务商 | 入口使用漏斗图标 | 图标含义与全部、已启用筛选相符 |
| 添加一批模型后再添加 | 模型区的加号持续打开目录，手动添加另有明确入口 | 完成一批后可重新打开目录，已添加项保持准确状态 |

历史列表标题取自第一条提问，不额外调用模型。列表按更新时间读取，草稿保存在当前工作区内存；重启恢复的是已保存的对话，不承诺未发送草稿跨重启保存。新建等待期间暂时禁用历史切换，原对话仍可编辑；回执读取最新草稿，不用旧闭包覆盖后续输入。

四种文本协议是 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Generate Content。Cherry 的图片端点、云账号认证和同服务商多端点编辑未接入，不能把此轮描述为整个 Cherry 产品的全部协议能力。用户显式保存的根地址保持原义，不自动追加版本路径。

## 实现与来源

- [Cherry 协议接入](../research/cherry-protocol-reuse.md)：固定版本的文本端点映射、原生请求和目录规则。
- [模型目录选择](../research/cherry-catalog-selection.md)：常驻入口及用户指定的勾选后确认流程。
- [ChatLab 对话历史](../research/chatlab-ai-thread-reuse.md)：按原始会话分组、独立线程与无损迁移。

数据库由版本四迁移到版本五，取消每个原始会话只能有一条 AI 线程的限制，保留旧编号、问答、用量和关联。删除原始会话时清理其全部线程，其他会话不受影响。

## 检查记录

新行为先运行失败测试再实现。独立复核发现异步创建期间草稿覆盖、旧根地址被补版本路径两处问题，均补充失败回归后修复。桌面验证另发现历史列表在 1200 像素窗口遮挡模型入口、分栏后原文标题被工具栏挤压；修复切换条件和换行规则后，原失败场景通过。

- 前端全量测试：26 个文件、240 项通过，包括发送交接、草稿恢复、窄窗历史列表、全选确认和部分保存失败。
- 后台全量测试：31 个文件、409 项通过，包括旧库迁移、四种原生协议、独立线程和跨会话隔离。
- 桌面全流程：9 项通过，覆盖对话、设置、目录选择、导入、引用跳转、选择本人和窗口控制。最后调整原文标题换行后，AI 对话与窗口布局两项再次通过。
- 类型检查与桌面构建通过。Impeccable 扫描本轮 10 个界面文件，未报告其规则所覆盖的问题；视觉验收仍以实际截图和鼠标操作为准。
- 1280、960、360 像素窗口实测关闭按钮位置及命中；窄窗同时断言正文与输入框不被主侧栏遮住。截图停在动画结束后的状态。
