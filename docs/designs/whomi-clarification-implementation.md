## 已实现

| 功能 | 当前行为与场景 |
|---|---|
| 问题与情景 | 问题框呈现背景和待澄清问题；回顾那段情景复用会话完整消息范围。例：虚构答辩问题定位 plan-1 至 plan-10 共 10 条消息，返回解惑后仍是原题 |
| 三张预置卡牌 | 内容直接可读，桌面轻扇形排列，鼠标悬停和键盘焦点抬起牌面；点击、Enter 或空格立即发起提交。没有以上都不符合卡牌 |
| 自己回答 | 输入提示为以上都不符合，我有自己的想法…；进入输入框后卡牌不可选，改用卡牌回答恢复选卡并聚焦首牌。例：草稿写了一半切回选卡，草稿保留且不会混入卡牌答案 |
| 输入栏与模型 | 自增高输入、可用模型选择、发送按钮；Enter 发送、Shift + Enter 换行，中文组合输入不会误发送。无可用模型时可编辑草稿，自己回答不能发送；卡牌提交不要求选择模型 |
| 提交与撤回 | 同题同步加锁防止连点；提交成功锁定作答，撤回成功才能重新选择。失败保留原回答并提供重试，提交失败后聚焦重试入口。例：撤回正在等待时，原回答仍显示，输入只读 |
| 来源与导航 | 来源失效时禁用回顾入口并说明原文暂不可用；阅读页根据来源返回解惑或个人总览。品牌返回 Hello 移除个人内容，解惑状态保留在当前应用实例中 |
| 适配与键盘 | 窄屏与主区空间不足时改为单列卡牌，长文本自然增高；输入区不固定覆盖正文或焦点。减少动态效果时关闭卡牌变换，强制颜色模式保留边界 |

采用现有 React、普通样式表、Tooltip 所在导航体系和 Lucide 图标，没有新增依赖。输入布局参考前期组件调研，未复制第三方源码。

## 接口与状态边界

- `src/components/clarification/types.ts`：问题、选项、可用模型、回答、提交回执、撤回回执及控制器类型。
- `useClarification`：按问题标识保存模式、草稿、模型、提交快照和异步状态，位于应用壳内，页面切换不销毁本轮作答状态。
- `ClarificationPage`：展示与键盘操作；只调用传入控制器，不调用模型或存储。
- `App` 接收可选 `clarificationQuestion`、`clarificationModels`、`clarificationAdapter`。来源继续使用已有 `SourceReference`，会话阅读返回入口改为通用 `onReturn` 与 `returnLabel`。
- `ClarificationAdapter.submit(questionId, answer)` 返回 `answerId` 与 `persistence`；`withdraw(questionId, answerId)` 返回撤回回执。`persistence` 为 `saved` 或 `preview`，界面分别显示真实提交和模拟提交，不表示画像已更新。
- 未传适配器时，卡牌提交、输入发送和撤回不可用；可编辑草稿，不产生假成功。

本轮所有草稿、答案和模型选择仅在当前应用内存中保留，刷新或关闭后丢失。没有增加本地存储、数据库或网络请求；现有侧栏偏好保存保持原行为。问题生成、每日额度、跨日恢复、真实模型配置、保存与撤回业务、后续分析修正均未实现。未来接入方应提供稳定问题标识及真实回执，并负责未答问题的持久保持，不能将前端状态当作后端能力。

## 预览方法

运行 `npm run dev`，打开 `/preview.html?page=clarification`，点击侧栏解惑。该地址仅预选开发工具的解惑场景，启动仍先显示 Hello。

预览控制提供六种场景：选卡与自己回答、暂无问题、无可用模型、原文不可用、长问题与长选项、未接入提交接口。回答提交和撤回分别支持正常、等待手动完成、首次失败后重试成功、始终失败。

例如，选择撤回模拟为等待手动完成，点击撤回回答后看到正在撤回；在预览控制点击完成模拟撤回，才回到原题。没有用计时器假装完成。所有问题、对话、模型和回执都明确标为虚构或模拟，未写入真实存储。

正式入口不传问题、模型或适配器。2026-10-29 起，无问题时主区中央显示浅色单句疑问今天请假了，不显示可见标题、旧版暂无待澄清的问题或返回 Hello 按钮；保留隐藏一级标题供屏幕阅读器和导航焦点使用，仍可通过品牌及侧栏导航离开。生产构建不包含 preview.html 或虚构场景。

## 2026-10-29 空状态修订

本次仅调整无问题状态的展示：删除可见解惑标题、暂无待澄清的问题及返回 Hello 按钮，改为主区中央的浅色单句疑问今天请假了。隐藏一级标题继续承担屏幕阅读器名称与导航聚焦，品牌和侧栏导航保留；有问题时的卡牌、输入、模型选择及回答流程不变，不增加实际数据或算法能力。

场景：用户从正式首页 `/` 点击解惑，尚无问题时只见中央提示；点击品牌仍可返回 Hello，无需页面内重复放置返回按钮。

本轮解惑组件与导航相关的 12 项测试通过，`npm run build` 通过。浏览器检查 574 × 892、1280 × 900 两种视口，提示中心与主区中心重合，没有横向溢出；窄窗主区中心与提示中心均为 x 327、y 446。文字与浅灰背景的计算对比度为 4.64:1；系统高对比度与屏幕阅读器未实测。截图见[窄窗口空状态](assets/clarification/empty-state-20261029-narrow.png)和[桌面空状态](assets/clarification/empty-state-20261029-desktop.png)。上节 103 项测试及旧截图仅对应 2026-10-28 版本，不作为本轮全量回归证据。
