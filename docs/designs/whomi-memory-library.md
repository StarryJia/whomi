2026-10-31 确认的产品与界面设计。本文是本功能命名、阅读入口、文稿模板及验收的依据。0.1.6 桌面版已接通仓库、事件归并和三节文稿，旧的 `conversation-analysis-v1` 任务保留原执行路径。下方可交互页面为设计样稿。

## 从原会话生成，到仓库阅读

| 用户所在位置 | 界面约定 | 可观察的结果 |
| --- | --- | --- |
| 原会话工具栏 | 入口叫「整理成记忆」。打开后核对当前会话范围和生成模型，主操作为「生成记忆」 | 用户取消后回到原文。确认生成才启动任务。 |
| 生成中或已暂停 | 原位置显示任务进度，提供「暂停生成」或「继续生成」 | 例如进度已保存至 8/24，关闭程序再打开，用户从同一份记忆继续。独立的「重新生成」须再次确认。 |
| 生成完成 | 「查看记忆」转到侧栏「记忆仓库」，按本次任务编号打开对应文稿 | 即使同一会话已有两份成稿，打开的也是刚完成的那份。 |
| 记忆仓库 | 导航名称和页面标题均为「记忆仓库」。使用与其他导航项同尺寸、同线宽的 Lucide `Archive` 收纳盒图标 | 侧栏折叠时，提示及辅助技术名称均为「记忆仓库」。图标只承担导航，不是归档或删除按钮。 |
| 阅读文稿 | 仓库采用 B 方案：按会话分组；会话与其中的「未完成」可独立收展。点开后在仓库内弹窗阅读，窄屏可使用全屏阅读窗 | 关闭或按 Escape 返回原列表行，恢复焦点和列表位置。空仓库在文稿列表的位置展示《我们的记忆》格式预览。首次使用可导入记录，有记录可选择会话进入生成确认。点击「继续整理」直接恢复该编号的任务；已经在生成的任务只打开，不重复启动。 |

《我们的记忆》是生成的文稿。仓库可用「我和小林」标识来自哪段会话，同一会话有多份时进一步区分。一次生成任务产出一份文稿，分批或断点续跑均属于这同一份。例如同一会话里，成稿 #0006 和未完成的 #0010 各有独立的浅灰编号；续跑不改编号。「创建于」是任务建立时间，「生成于」是成稿完成时间。成稿显示带年份的聊天起止日期和实际生成模型，缺少记录时不猜测。右键会话或记忆可置顶、取消置顶或删除；删除记忆经确认后只影响该任务，保留聊天和其他记忆。此处编号为示例。

## 文稿的开头与正文

打开文稿时，先显示标题，再用一小段文字说明其性质。声明位于正文之前，只出现一次。建议文案为：

> 根据聊天记录写成的娱乐解读，仅供参考。

声明由阅读界面统一呈现。从原会话跳转或从仓库点开，读到的都是同一段开场声明。正文按以下顺序使用三个固定标题，直接显示标题名称，不加数字、章次或额外的解读标签。

| 标题 | 写作约定 |
| --- | --- |
| **MBTI 预测** | MBTI 指迈尔斯–布里格斯性格类型指标。先显示已确认的本人在这段关系中的四位结果，再逐维给出中文倾向和字母。例如，结果为「?SFP」时，「理解信息」显示「偏向实感 S」，下方接文稿保存的原因；「精力来源」显示「暂难判断」。旧稿只展示已保存的结果。 |
| **我们的记忆** | 挑出讨论分量最大的几件共同经历，按经历顺序叙述。每件事用能认出来的短标题和自然段，写清缘起、进展和已知结果。事情尚未落定就写到已知进展，不凑数。 |
| **我们的关系** | 从整段经历出发，自由谈相处方式、气氛或有意味的变化。区分 AI 的印象和已经发生的事，不机械地用 MBTI 解释关系，不逐条列依据或打关系分。 |

**虚构示例。** 「我们的记忆」里写 *那次电话试讲*，概括小林为周五的汇报发愁，两人约了十分钟通话，后来小林说开头顺了些。「我们的关系」则可以写 *你问了他想怎样被帮忙，小林也说得出只想试讲十分钟。你们似乎给彼此留了一点余地。* 前者让人认出共同经历，后者给出对这段关系的一种读法。

## 生成与兼容约定

- 读取聊天可以分批，选材以完整事件为单位。第一批商量搬家，中途聊工作，后面又约同一次搬家的货车时，应归为一个事件。先在同一会话内归并，再按去重后的有效讨论量选材，跨批重叠不重复计数。正文不展示消息编号或证据清单。
- 版本化生成指令应分别返回本人的性格预测、主要事件和关系解读。阅读界面使用固定标题及开头声明。旧报告的「摘要、观察及限制」与新结构并不等价，历史成稿按实际保存内容阅读，不为旧报告补造预测。
- 每次任务绑定原文快照、处理设置和提示词版本。已保存的批次或汇总可复用，未保存的部分重新请求。设计要求旧暂停任务能按原版本续完；实现新版本时需验证兼容，避免混用两版结果。

## 设计验收

1. 从原会话点「整理成记忆」只进入确认。生成完成点「查看记忆」，仓库导航高亮并打开正确文稿；从侧栏进仓库也能找到同一份。
2. 弹窗内容顺序为标题、开头声明、MBTI 预测、我们的记忆、我们的关系。三个正文标题不带「第一章」或「01」等前缀，声明不会在类型旁或正文末尾再出现。
3. 仓库图标是收纳盒，展开、收起和键盘聚焦时均能识别入口。宽窗和 360 像素窄窗都能读到关系解读的末尾，关闭后回到原条目。
4. 同一事件跨批仍只占一条记忆。暂停再继续仍是一个仓库条目，主动重新生成并成功完成才产生另一份。
5. 用三组虚构材料核对「MBTI 预测」。只约定时间、互发地址时显示「????」，后两节仍可阅读。若只有安排方式可判断，显示「???J」，其下可读到本次聊天支持这一判断的具体原因。四个维度都可判断时才显示完整类型。汇总到个人总览时，未知维度不贡献方向，也不计作两侧均衡。

## 0.1.7 的关系计分

每份新文稿先归并事件，再按维度计数。只采纳已确认本人主动选择的证据。至少三件独立事件、其中至少三分之二同向才给出这一维的倾向。总览按关系投票，至少两段关系在该维可判断，每段一票。换人后撤回原关系对总览的贡献，仍可在仓库阅读历史成稿。
