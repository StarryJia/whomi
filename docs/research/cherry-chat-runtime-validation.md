## A15 长会话已通过

测试使用两个隐藏的 Electron 窗口、各自的临时 SQLite 数据库和本机合成模型。每次从数据库恢复 200 轮示例历史，在输入器发送第 201 轮。回答在 1280×800 时持续增长，切到 960×720 后继续增长，再通过界面停止。两次串行复跑均以退出码 0 结束。构建版使用 `index-Cy7Pe1st.js`，开发版由 Vite 提供同一工作树的渲染代码。[构建版原始记录](assets/cherry-chat-migration/a15-200-rounds-built.json) · [开发版原始记录](assets/cherry-chat-migration/a15-200-rounds-dev.json)

| 运行方式 | 已恢复轮次 → 停止时轮次 | 持久文本增长与停止时字符数 | 停止后静置 | 滚动偏移 |
| --- | ---: | --- | ---: | ---: |
| 桌面构建版 | 200 → 201 | 840 → 1320，缩窄后到 1680，停止时保留 1800 | 3014 毫秒 | 0 像素 |
| Vite 开发版 | 200 → 201 | 600 → 1200，缩窄后到 1680，停止时保留 1800 | 3003 毫秒 | 0 像素 |

两版均采集原生窗口错误（`window.error`）、未处理拒绝（`unhandledrejection`）、Playwright 页面错误（`pageerror`）和错误级控制台消息（`console.error`），各类记录均为 0。正式复跑使用浏览器原生尺寸观察器。该产物包含输入器延后交接、提交待受理时的焦点处理，以及打开已有会话时的引用保留。尺寸调度由独立的固定依赖补丁控制。

## 基线与迁入版小样本

从 `b6378890e14796e131c37a67ef432e7cf58298d9` 提取的基线在同一台 Windows 机器上重新构建，渲染入口为 `index-D1QYg9cY.js`。性能采样使用的迁入版入口为 `index-CuLMu8pG.js`，早于上节的最终 A15 构建。两版共用安装依赖目录，每个样本用独立的 200 轮合成数据库。隐藏窗口交替采样三次，在打开 AI 对话后等编辑器可输入，输入同样的 50 个英文字母，确认收到 50 次输入事件及完整文本。加载时间包含自动化开销。这些观测对应本次机器、渲染产物和窗口条件。[采样数据、运行环境与产物哈希](assets/cherry-chat-migration/a15-runtime-comparison.json)

| 指标（毫秒，按采样顺序） | 基线 | 迁入版 |

| 启动到自动化附加首个窗口 | 852、828、887 | 823、886、880 |

同条件的滚动性能对照未完成。隐藏基线的三个样本从底部上滚 600 像素，静置至少 3 秒后仍是同一锚点，锚点位置和滚动偏移变化均为 0 像素。隐藏迁入版先发生虚拟列表范围重测，实际滚轮稍后才生效，首轮探针过早开始静置计时。追加隐藏探针在超时前没有确认距底增加。改为两个非激活可见窗口时，两版都在等待输入文本的下一动画帧时超时，未到达滚轮步骤。上述失败保留在本地 `artifacts/cherry-chat-migration/diagnostics/a15-runtime-comparison-*.json`，不用于比较滚动耗时。

独立的正式桌面阅读用例通过真实滚轮向上阅读，流式增长时同一锚点保持在原位置。长会话 A15 的静置位移也已在上节记录。两项功能证据分别来自各自的场景。[桌面阅读用例](../../tests/desktop/reading-polish.spec.mjs)

## 尺寸观察器的来源和补丁

未打补丁的构建版在短合成会话中记录到 3 条原生尺寸通知。回调跟踪显示，virtua 在同一次尺寸交付内同步修改虚拟列表总高度、行位置和已观察的行，浏览器紧接这次提交报告未交付的通知。只延后 Whomi 会话容器自身的回调，仍记录到 3 条通知。

安装时对固定的 virtua 0.49.1 React 入口应用小补丁。它在观察器所属窗口的下一动画帧交付测量，合并同一目标的最新条目，并在取消观察和断开连接时清理等待交付的条目。脚本核对模块和 CommonJS 两个入口补丁前后的 SHA-256 摘要，版本或文件摘要不符时停止。连续应用与调度器生命周期验证通过，原始许可随来源记录保留。[补丁脚本及校验值](../../scripts/patch-virtua-resize.mjs) · [调度器源码](../../src/vendor/virtua-resize/defer-resize-observer.mjs) · [来源与许可](../../src/vendor/virtua-resize/UPSTREAM.md)

首次并行复跑时，开发版在启动准备阶段超过 20 秒，构建版完成场景采样后因临时词典文件被占用而无法完成清理。两次均属诊断记录。早期用于区分两类观察器的单独延后实验还曾因异步等待条件写错而提前退出。通过结论只采用最终串行复跑的完整记录。

## 隔离副本的界面回退已通过

使用最终迁入版 `index-Cy7Pe1st.js` 在一个临时数据库中保存两个示例轮次。第 1 轮正常完成并引用原文 1，第 2 轮在流式输出后停止，保留「示例停止时保留的回答。」并引用原文 2。关闭应用后，将数据库和预写日志复制到另一个独立临时目录，逐文件核对 SHA-256 摘要。

基线 `b637889` 的桌面构建打开副本，两轮的编号、请求编号、状态、正文、模型身份和引用编号全部一致。基线界面显示两条回答、停止提示和两个引用入口。点击停止轮的引用，原文窗口高亮消息 2「示例回退原文乙」。模型服务共收到两次请求，均来自迁入版保存示例轮次。验收对象是隔离数据库副本上的界面回退。[基线读回原始记录](assets/cherry-chat-migration/interface-rollback.json)

## A04 Windows 输入法尚未验收

隔离工具打开了标题为 **Whomi 输入法验收（合成数据）** 的正式构建窗口和示例会话输入器。Windows 自动化获取窗口画面超时，恢复到可读控件树后仍无法取得坐标或给输入器焦点。窗口关闭前记录到 0 次输入事件、0 轮持久对话和 0 次合成模型请求。这批数据只能说明本次未执行到真实选词和发送。A04 的验收仍需在 Windows 输入法中按回车选词，再用发送键提交并核对只保存一轮。

本地诊断目录为 `artifacts/cherry-chat-migration/diagnostics`。其中 `a15-200-rounds.mjs` 从项目根目录以 `built` 或 `dev` 参数运行，`ime-observation.mjs` 准备输入法隔离窗口，`ime-observation.json` 记录本次窗口关闭前的观察结果。
