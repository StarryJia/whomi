# Windows 桌面会话导入验收

2026-10-30；Whomi 0.1.0。本轮只使用项目自行编写的虚构数据，不读取私人聊天；没有模型调用或自动分析。本文记录本机观察，不能推导所有导出器版本、历史数据或硬件均兼容。完整支持结构与许可边界见[14 格式矩阵](chatlab-parser-reuse.md)。

## 已有能力与操作

桌面侧栏会话旁加号进入导入页，可以选择或拖入文件/文件夹。勾选发现的入口并解析，预览每页最多 50 条消息；确认导入目标和本人身份后保存。保存结果可打开会话；重启后展开会话列表重新打开。每个会话在一个正式事务内保存，部分会话失败时保留其他会话已经提交的内容。导入不会自动发起模型分析。

虚构验收：第一次文件含 m1、m2、m3，第二次目录只含正文改写的 m2 和新 m4。第二次新增 1 条、第三次同文件新增 0 条；重启后共 4 条，保留原 m2 正文，m1/m3 不因新文件缺少而删除。明确的平台消息标识只在其来源会话与命名空间内去重；不能用正文、文件名或显示昵称推断跨导出身份。无可靠标识时只允许保守归属，不能承诺任意两份导出自动合并。

读取默认每页 100 条、最大 200 条，界面最多保留五页。真实 Electron 窗口加载六页后，节点仍为 500；向前/向后恢复一页时，可见消息相对滚动容器的位置误差不超过 2 像素。稳定本地编号跨重启保留，locateSource 返回所属会话内的原文及前后文。现有总览/解惑没有真实模型产物，当前没有新增来源入口来伪装已完成分析。

媒体仅保留类型、名称与未解析/缺失描述；不复制、播放、解密或下载。单文件受限全量解析最多 32 MiB，ChatLab JSONL 流式最多 2 GiB，原始行及规范化消息最多 8 MiB；限制是实现门槛，2 GiB 没有真实生成并实测。目录最多 16 层、10,000 项。多会话写入按会话事务执行，500 条或 8 MiB 仅是让出事件循环的批次，不是正式提交边界。

## 验收方法与失败重试

- `npm run test:desktop -- --case import`：真实磁盘文件与目录通过 Chromium 开发工具协议拖入产品组件，点击入口、预览、目标、本人及保存，再关闭和重开应用。恶意脚本/图片标记作为正文文字显示，没有脚本元素或执行结果；源树摘要保持不变。
- `npm run test:desktop -- --case crash-recovery`：真实数据进程在 COMMIT 前/后退出。前者不留半批消息；后者重启仍可读且重导新增 0。后端还覆盖实际子进程被终止、SQLite 写入故障与取消回滚；不是只用网页预览推断持久化。
- `tests/backend/import-contract.test.ts`：14 个格式的虚构正例均走同一发现、快照、暂存、预览、目标保存、同文件重导、关闭数据库重开、分页与定位合同。Telegram 全量为 2 个会话共 4 条，其余逐格式计数见矩阵。格式探针、损坏、缺字段与巨大记录分别由解析/暂存用例覆盖。
- `discovery/staging` 用例覆盖目录越界、联接、扫描后替换和文件变更；`merge/runner/recovery` 用例覆盖回滚与已提交结果通知丢失。数据进程和主进程均拒绝把运行测试目录联接到别处。

例如入口显示原文件改变，重新选择来源、解析并预览后再保存；磁盘写入失败先释放空间，再重新选择失败的来源。已保存的结果可以直接打开，无需删除旧资料；重复消息会跳过。摘要失败只需点重试摘要，消息保存结果不因此撤销。尚未实现断点续传和会话删除。
