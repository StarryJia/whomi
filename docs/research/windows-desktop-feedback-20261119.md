## 安装目录复测

2026-11-20，从包含 #37 的 `c50cabf` 构建 Windows 安装包，解出其中的 `Whomi.exe` 与应用资源，核对两者与构建输出的 SHA-256 摘要一致。在 Windows 10 上将程序放入 C 盘临时安装目录，用户配置另放，随后把会话数据迁到 D 盘。

- 「打开错误日志目录」请求打开程序旁的 `logs`；更换数据目录并重启后路径相同。模型连接故障、洞察超出输出预算均在这里留下记录。导入内容为 `{"incomplete":` 的测试文件后，「查看错误日志」定位到 `logs\import-errors` 下本次任务的 `.txt` 文件。旧任务仍可打开自己的导入错误记录。
- 拒绝当前用户写入测试安装目录中的 `logs` 后，打开日志目录会提示具体路径和恢复写入权限的操作。数据目录和用户配置未产生新错误日志。恢复权限后重试，日志写回安装目录。桌面回归 3 项通过，打开系统查看器的调用由测试拦截。
- 用独立临时安装目录运行与安装包相同的升级清理脚本。模拟旧程序文件被占用时，升级中止并恢复原文件；释放占用后升级清理成功。普通错误日志和导入错误日志的内容摘要在清理前后一致。

本次类型检查通过，前端全量 646 项、后端全量 757 项通过。

维护者确认 [#33](https://github.com/StarryJia/whomi/issues/33) 按实际安装位置验收。例如在「设置 → 数据存储」点击唯一的「打开错误日志目录」，可在 `Whomi.exe` 同级的 `logs` 中找到刚触发的错误。修复合入 `main` 后可关单。
