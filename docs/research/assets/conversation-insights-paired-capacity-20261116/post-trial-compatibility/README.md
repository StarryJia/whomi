# 真实对照结束后的本地摘录兼容修复

本快照与真实模型对照的冻结实现分开保存。全部真实模型调用结束后，本次只运行本地回归、类型检查和保存响应的零网络回放；新增模型调用为 0。真实对照中的报告、评分、请求记录、费用与失败结果保持原样。

本次修复允许候选更新复用当前请求实际显示的任意候选已验证摘录。来源编号必须一致，引用必须连续包含在单条已验证摘录或本批原文中。隐藏摘录、补写未见文字、拼接不同摘录仍被拒绝。新候选仍只能引用本批原文；主动核查仅复用当前核查请求实际显示的摘录，旧摘录不能替代当前分片的原文摘录。提示词、候选触发条件、容量和调用预算未修改。

例如，当前请求已显示来源 62 的已验证摘录，模型更新另一个可见候选时可以引用其中连续的一句；不能据此引用来源 62 未显示的后半段。该兼容性按实际可见证据判断，不额外按候选归属限制。

## 本地验证

- `evidence/quote-visible-scope-red.log`：跨可见候选摘录用例先失败，隐藏候选摘录拒绝用例通过。
- `evidence/quote-visible-scope-green.log`：专项测试 104 项通过，含新增摘录边界 15 项。
- `evidence/quote-visible-scope-typecheck.log`：类型检查通过。
- `evidence/quote-visible-scope-replay.json`：使用实际保存的 baseline B 第 4 次请求与响应，直接调用当前解析器，网络调用为 0；原产物哈希未变。
- `evidence/quote-reuse-replay.mjs`：回放脚本仅在内存临时导出已有解析器，响应控制副本也仅存在于内存。

原 baseline B 第 4 次响应仍因支持与反例编号重叠而返回 `INVALID_INSIGHT_OUTPUT`。仅在内存副本中移除重叠后才通过解析。这证明已显示的旧摘录可以复用，不代表原响应有效，不追认原失败试验成功，也未恢复该真实任务。

## 快照边界

`source/` 保存最终生成逻辑、新增回归和固定响应夹具，并保存未变的提示词作为核对依据。`manifest.json` 列出全部文件的 SHA-256、原冻结实现哈希及本地证据来源。`evidence/post-trial-generation.diff` 仅展示相对真实对照冻结版的生成逻辑差异。

完整后端测试、工具测试、构建和桌面验收由主代理单独追加记录，本快照创建时不代替这些验收，也不新增真实模型证据。
