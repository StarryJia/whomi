## 能比较什么

第一组保有四份报告，可以比较相同材料和容量下的新旧输出。第二组旧版在通读中停止，缺少两份旧版报告；只能对最终新版两份报告做独立原文评审，不能补造完整配对或计算新旧准确率。

匿名文件逐字对应原报告的正文、引用与限制说明，六份投影及映射摘要均已核对。评分先于揭签，由独立代理按四项各 0–5 分作定性判断，不是人工验收、统计准确率或可推广的性能估计。原评审文字保持原样；第一组中的人工等级评价一词指评分形式，不应理解为人类已验收。

`adaptive` 是允许模型选择核查的路径，`direct` 是直接使用同一通读底稿写作的对照。新版两组都没有提出候选或发出主动核查请求，因此这几份报告之间的差异不能证明回读收益。第一组新版事实保留较好，但仍出现把回答借书问题写成答应借书、引用与具体论断不匹配的问题；第二组仍把已确认办理的订金状态写成整体未知。15 与 14 的一分差距也不足以证明稳健优势。逐条依据见[第一组匿名评审](reviews/paired-shared-workload/blind-review.md)、[第二组匿名评审](reviews/paired-conditional-reschedule/blind-review.md)及[揭签汇总](reviews/revealed-summary.json)。

## 两个保留的失败

初始 current 在第 10、11 次响应中保留了全部输入条目，压缩体积分别减少约 35% 和 39%；旧校验因第 87:0 条已知条目只出现在未知分类而拒绝，运行以 `INVALID_INSIGHT_OUTPUT` 结束。它没有报告，也没有按后来规则追认为成功。[失败摘要](offline/paired-capacity-current-failed-summary.md)和原始 `halt.json` 均保留。

旧版第二组第 4 次响应有两个独立拒绝点：新增摘录重复了候选中已显示的 62、63，但不属于本批原文；同时支持列表与反例列表都含 62、63。冻结旧实现先在摘录校验处拒绝，单独去掉任一问题仍失败。仅在内存中同时去掉两项的零网络控制可接受该批；此控制不算原试验的已接受响应，也不改写候选状态。前三批实际接受 72 条，失败批次 73–90 未接受。[失败审计](offline/paired-capacity-baseline-conditional-failure.md)保留四项控制和原件摘要。

## 试验结束后的本地修复

[独立兼容修复快照](post-trial-compatibility/README.md)保存了真实调用全部结束后的另一版实现，没有新增模型调用或恢复任何真实任务。该版本允许更新候选时复用当前请求实际显示的任意候选已验证摘录：例如已显示来源 62 的一句话，可以连续引用该句的一部分；不能借此引用来源 62 未显示的文字、拼接两段摘录或改写补字。新增候选仍限本批原文，提示、触发条件、容量与调用预算不变。

该修复的专项 104 项测试与类型检查通过。对旧版第二组响应 4 的零网络回放仍因支持与反例编号重叠而返回 `INVALID_INSIGHT_OUTPUT`；只有在内存控制中去掉重叠才通过解析。原试验仍按原冻结实现记录为 `INVALID_EVIDENCE` 失败。兼容修复没有重新做真实模型验证，不能据此改写本轮成稿、评分或失败结论。其源码、回放、红绿记录及相对真实冻结版本的差异均在单独目录，真实试验使用的两个冻结目录保持原样。

最终补丁完整后端为687项通过、1项失败，并有同一Grok登录失败的未处理错误；56121仍位于本机56028—56127保留端口范围。工具36项与桌面构建通过。定向桌面流程首次在受限环境60秒超时，没有具体断言；同一用例在正常用户执行环境带诊断重跑1项通过，总时长9.5秒，测试代码未修改。首次失败及重跑均保留，不能仅凭重跑确定超时根因。[最终检查汇总](validation/summary.json)的postTrial单列上述结果，validation下的post-trial文件保留原日志。

用户反馈的0x80000003弹窗另有[既有启动诊断](validation/memory-desktop-baseline-debug.log)佐证：受限子进程无法读取Electron运行资源，触发致命检查后退出码2147483651即0x80000003。这证明至少一次同码失败发生在启动阶段，不能把无对应进程信息的每次弹窗或超时都归为同一原因。没有更改目录权限或关闭Electron自身沙箱。
