# 长聊天事实保留修复与复测

承接[想法004](../planning/ideas/004-conversation-insights.md)及[上一轮长聊天对照](conversation-insights-long-comparison-20261115.md)。用户明确授权先修复压缩丢失事实和来源、旧未知未被后文更新，再使用原模型与原两组合成材料真实对照，不人为触发回读。本轮从 `fee2af4` 继续，分支 `codex/issue-10-conversation-insights`；开工 fetch、pull 后相对远端 main 无落后提交。安装版、真实聊天、远端工单均不在修改范围内。

## 调用前固定的修复与验证设计

本节先于本轮任何模型调用保存。采用现有阅读、导航、预算和检查点机制，修复已定位的数据流，不增加新的模型服务或独立检索系统。

1. 压缩输出区分导航文字与供成稿使用的事实条目。模型按输入条目编号合并，程序继承对应完整来源并校验输入覆盖；原始叶笔记继续保存。事实文字是否忠实仍需真实语义核对，编号完整不能替代这项验收。
2. 旧未知与事实在合并中一起协调。已解决未知必须与提供答案的事实归入同组，不能直接丢弃。例如余额有效期已经明确并被接受，应保留规则及接受来源，同时继续保留另一位参加者尚未确认的独立未知。
3. 后续通读为旧事项预留容量，优先回复关联，再轮转较早事项；全局保存不再受单批输出条数限制。例如较早记录主持方式未改变，读到本人实际留出停顿时，应有机会关闭旧事项并保留新行为。没有看见的事项不得自动认定解决。
4. 成稿容量按实际事实内容衡量；不能通过删来源、默丢事项或临时扩大预算取得成功。原叶和已用预算在恢复时保留。

### 固定材料、模型和方法

- 模型沿用本机已授权的 chatgptPRO / gpt-6.1-sol，配置只读；不设金额上限的授权不等于无限请求。本轮实际派发最多64次，任务最多30次、400000输入词元、40000输出词元、20分钟有效时间；8个候选、每项最多4轮。输入估算上限7000、单次输出上限3000，与旧轮一致。单任务调用数在首个模型请求前由28修订为30，依据见下段。
- 两组仍各120条。`shared-workload` 消息摘要为 `6f63b461c034eacaebc473ea5637bef13119aae59e286fa1d449347d9c6af756`；`conditional-reschedule` 为 `907c6b680d1acc0e4c021e7ae6c26393d1fd144c9c6f45d6ee4a47b316640b2d`。摘要用于校验材料一致，不是质量分数。原文、回复关系、日期、范围、评分事实不改。
- 独立轮次 `memory-preservation-20261115`，输出到 `release/conversation-insights-20261115/long-comparison-runs/memory-preservation-20261115`。旧轮41次请求及失败产物完整保留；新轮不复用旧阅读检查点，因为需验证修复后的完整通读和压缩。
- 每例重新通读，冻结首次核查前检查点；按需方法与直接分析共享本轮成稿底稿，成稿指令及输出上限相同。仅按需方法真正派发了带原文的核查请求时，才运行带冻结通读摘录的直接分析；缺摘录则零请求跳过。原两主方法和第三方法的边界沿用上一轮。
- 先比较修复前后准确性，再区分本轮按需与直接分析。两轮阅读输入、批次、压缩结构可能因修复改变，不能把变化归因于单个提示词或回读。每组每方法只保留首次成稿，不反复抽样挑选更好报告。

**零网络预检后的调用前修订。** 初稿沿用28次任务上限。使用相同材料和已有笔记模拟容量后，初版预计17/18个阅读批次、10次首层压缩，加共同协调与成稿至少29/30次。精简重复协议，并为旧事项预留五分之一可用背景空间后，预计16/17个阅读批次、9次首层压缩，加共同协调与成稿至少27/28次。28次缺乏自然核查余量，因此首个真实请求前明确改为每任务30次；两例各30次加各一次直接和摘录对照，仍不超过64次。不是根据付费输出调整，也未缩小输入容量或修改材料。上述只是模拟估计，实际模型可能留下更多笔记或需要更多层，达到上限仍按规则停止。工具显式使用 `--task-call-limit=30 --run-id=memory-preservation-20261115`，不改变默认旧轮限额。

### 评分与停止规则

沿用上一轮逐项原文标准：明确事实错误或把已知写成未知、关键遗漏、引用语义支持分别记录。固定关注：分工中的九月反例与撤回、当期负担、73—75主持变化、98—100有限接手、105—113效果及未来未知；改期中的26局部放宽、28参加条件、61—62余额规则和同意、97—102实际改期及分歧、109—114截止与最终未知。收据照片是否发送、是否本人登录核验余额仍按旧轮的保守边界评分。

准确性改善须在相同事实清单上减少明确错误或消除旧的虚假未知，并检查是否引入新错误、丢掉关键条件、扩大不受支持的引用。继承的编号变多不等于引用更准确，另记无关来源混入。正文片段数量不同，不按缺口片段绝对数量排序；只删除错误句同时省略关键事实，不能称为完整修复。独立评审先看匿名报告与原文，再揭示轮次及方法；程序审计另外核对完整来源、派发、预算、候选轨迹。自动补充旧原文、首次核查携带原文、模型主动再请求原文分别统计。

自然候选更新须有阅读响应自行提出候选、后续实际收到同一编号、模型自行修订或解决、状态正确落盘。普通笔记修正、压缩合并和未知关闭均单列，不算候选成功。没有候选就报告该路径未验证；不增加触发性话术、人工候选或额外样本。

两例固定比较完成后停止。越界、非法来源或预算问题立即保留产物并停止受影响流程；压缩无收缩或容量不足也保留失败，不扩大预算。程序故障只有在保存原响应、回归和恢复依据后才可使用同一总账续跑；失败派发计入64次。成稿不额外修复或抽样。若未发生回读，不能声称回读更准确或没有价值。

已用22/30次，剩余8次。按当时协议与6744的有效输入估算容量精确打包，未处理的126个原始条目还需要9次首层压缩，再加至少1次成稿，最低10次，尚未计跨块协调。即使离线接纳已经返回的第9次响应，也仍超出剩余名额。因此本轮保留停止状态，不通过删源、跳过未知协调或扩大预算取得报告。[容量与收缩依据](assets/conversation-insights-memory-preservation-20261115/offline/mixed-fact-audit.json)
