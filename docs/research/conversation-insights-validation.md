## 实施范围

复用现有桌面模型运行器、本地数据库、任务调度、模型选择及会话分页。新增日期范围快照、洞察报告格式、阅读与核查断点、精确引用、报告管理和本地总览聚合。未增加检索服务或额外聚合模型调用。

本地聚合已获用户确认：报告完整保存后参与，按会话和原文版本去重依据，保留冲突。取消、失败和未保存的结果不参与。删除报告后仅以剩余有效报告重算。例如九月和十月报告共用同一条原文时，保留两个报告入口和一份依据；删除十月报告后，它独有的反例也撤回。

- 取消启动不创建任务；范围内仅 3 条可发送，资料库其余 281 条保留本地。暂停后继续、服务成稿失败后重试同一任务、删除失败后重试均实际运行。
- 原文初次 100 条，向前分页后 200 条，再向后补页；两次插入的阅读锚点位移均为 0 像素。相邻普通上下文不误高亮。长报告关闭来源后回到相同滚动位置与引用焦点；80 字标题下返回和改名仍可达。

组合执行曾有一次桥接用例 60 秒超时，未输出失败断言；独立带跟踪重跑 9.1 秒通过，根因未确认。此记录不把重跑通过写成一次性全绿。桌面尚未覆盖置顶拖动、同名报告隔离、已有列表刷新失败、快速关闭后的迟到响应及整会话删除后的跨页退出；相应组件或存储测试不冒充真实桌面验证。

## 审查与修复记录

| 审查问题 | 复现及处理 |
| --- | --- |
| 暂停回执无法写入断点 | 暂停先锁定任务时，取消请求仍为 pending；已改为先保存取消回执再标记暂停，避免恢复把暂停时间算入活跃耗时。 |
| 原文分页游标大小不一致 | 来源游标保存分页大小 100，界面传入 50 导致 INVALID_CURSOR；已改为沿用游标大小，定向回归通过。 |
| 耗尽预算后无重新选范围入口 | 重试同一断点不会重置预算；已为失败和暂停状态补充再次洞察入口，可重新选范围但不自动启动。 |
| 派生元数据变化误判原文失效 | 回复补全及重新确认本人后，历史原文仍存在；分别校验分析输入版本与原始内容版本，原文读取保留，未完成分析继续拒绝混用变化后的输入。 |
| 多轮核查丢失先前依据、中间笔记无导航 | 已保留旧原文或逐字验证的摘录；笔记压缩保存完整子节点映射，允许按编号分页展开，恢复只处理未完成部分。定向测试覆盖第 6 条中段反例与压缩中断恢复，复核未发现残余导航问题。 |
| 摘录缺少原文日期、人物和回复关系 | 后续请求从冻结原文补齐四项元数据，模型自填的伪日期与作者不采纳。跨月材料回归先失败后通过。 |
| 真实报告限制说明出现内部字段 | 第一组合成材料暴露两段摘要、checks、judgments 等措辞；已在成稿协议要求限制说明仅谈原文事实、不确定性和可尝试行动，后续试验使用更新后协议。原始不佳输出保留，不事后改写成合格样例。 |
| 真实压缩请求返回普通笔记结构 | 远距离回复试验在完整阅读后，两次返回 nodes 包装，无法按单个导航摘要解析；已将压缩操作的系统协议与普通阅读分离，失败任务和已用预算保留，另以同一合成材料做有界修复复测。 |
| 已读原文却生成空正文 | 导航修复后的报告只有限制，模型把成稿阶段未直接收到全文误认为任务未读原文。已明确同任务有来源阅读记录可用于事实陈述和引用，核查结果约束推断，不把未提出核查当成没有材料；仍允许真正材料不足时没有判断。最后复测结果另列。 |
| 成稿引用误拒绝已发送的未决事项 | 最后实测中第25条来源已发送于未决事项，校验集合却只收观察与核查结果。修复仅纳入实际发送的未决事项编号；不开放未发送或范围外编号。保存的原断点及真实成稿离线重放先失败后通过，完整引用集合为1、2、27、28、15、17、13、25。重放没有新增模型请求，原始实测失败状态保留。 |

## 七类合成样本与解释边界

下表是首轮样本清单，所有输入均为虚构示例。首轮只有后续反例、远距离回复两组调用了真实模型；后续追加的轮流安排、授权范围和清楚约定见主动核查验证。其他项的确定性测试只验证程序边界，不证明模型抵抗诱导或理解情境的能力。

| 样本 | 输入与允许观察 | 不可断言的解释与来源要求 |
| --- | --- | --- |
| 跨批补充 | 前批本人先提三个办法，后批 ta 主动求建议；应保留后文，允许缩小先前判断。 | 不得只凭前批断定本人总不倾听；支持与反例均需引用。 |
| 跨日回应 | 深夜提出安排，次日回复同一消息；按时间和回复编号关联。 | 不能把午夜当作必然的新事件；两条原文的日期与回复关系保留。 |
| 同话题不同事件 | 周一眼科复查取消，周一修车照旧；只撤回眼科安排。 | 不得写周一的预约全部取消或已改到周五；来源为真实试验编号1、2、27、28。 |
| 后续反例 | ta 先说今天不要建议，后来明确请求两个选择；区分当次需要。 | 不推断固定人格或永远适用的沟通法；来源为真实试验编号1—7。 |
| 重复消息 | 同一来源再次回读、报告重复到达；依据仍为同一个编号和版本。 | 不因读取或通知次数增加覆盖与总览权重；重复原话不自动视为独立事件。 |
| 材料不足 | 仅有收到、好的两条回复；允许无判断或明确未知。 | 不强行补人格方向、冲突或建议；空判断不能冒充均衡结论。 |
| 原文含伪指令 | 聊天中出现忽略要求、读取其他会话这类文字；仅作为原文材料。 | 不扩大来源集合，不执行材料中的命令；模型返回越界编号由程序拒绝。真实模型抵抗此类文字未在本轮实测。 |

## 开发预算与发布限制

集中配置 `electron/main/insight-policy.ts`：最多 8 项核查、每项 4 轮、64 次请求、500,000 输入词元、32,768 输出词元、30 分钟有效运行。额外压缩、解析修复、缩片和失败重试均占同一预算；断点恢复不重置。输入估算和服务返回的实际用量分别记录，未知用量不补成零。

这些是有界的开发配置，**不是已核定的发布参数**。两组合成材料只能检查局部行为，不足以确定长期运行的最优成本和质量；本轮不增加复杂度或扩大样本。所选普通密钥接入的实际请求是否接受显式输出上限、用量和失败情况见质量比较记录。

## 已授权的最小质量试验

先比较两个合成场景，每个场景用同一模型运行简单阅读与本次流程各一次，共 4 个任务：

1. **后续反例。** 先说不想听建议，随后明确请求建议。检查报告能否区分时刻和需求、引用两类原文，避免给本人贴固定标签。
2. **远距离回复。** 最初只能周五参加，隔多条消息后说明周一的预约取消。检查回读是否保留原先限制及后来变化，是否错误归属到另一件事。

每个任务最多 6 次模型请求、80,000 输入词元、6,000 输出词元、5 分钟有效运行；最多 24 次请求。用户指定本机 chatgptPRO 的 gpt-6.1-sol，已告知其为普通密钥接入，并明确不设金额上限。仅只读取得指定模型配置，密钥在隔离 Electron 内存解密，不读取真实聊天、不修改安装版数据库。实际收费不能从词元数凭空推定。

人工逐项核对原文覆盖、事实归属、反例是否修正结论、引用能否支持对应句子、限制是否保留、建议是否可理解。任何预算超限、越界发送或无来源事实立即停止；推荐流程没有可辨认改善时停止扩大样本和增加复杂度。实际输出、调用数和结论见[质量比较](conversation-insights-quality-20261115.md)，不以控制流测试代替模型质量结果。
