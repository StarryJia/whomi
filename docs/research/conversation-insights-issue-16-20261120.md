# 工单 #16 · 从报告回看引用原文

在 Windows 10 的 Electron 45.1.0 桌面窗口中，从报告的经历链接打开聊天、翻页、切换片段，再关闭弹窗。测试用本地合成聊天和报告，等待与失败由测试控制。报告生成时使用合成模型服务，浏览与切段期间的模型请求增量为零。

## 操作与结果

| 场景 | 实际检查 |
| --- | --- |
| 精确证据 | 在同一片段里，原文编号 1 和 3 带证据标记，中间的 2 保留普通样式。头像、原始发送者、时间、正文和回复沿用会话阅读器，弹窗里的回复只读。[非连续证据](assets/conversation-insights-issue-16-20261120/after-exact-highlight.png) |
| 自由浏览 | 初次读取 100 条消息，上翻后共 200 条。前插和后续追加前后，正在阅读的消息相对阅读区的位移均为 0 像素。浏览保持原片段计数，用键盘选择「回到引用」后，可以直接用方向键继续阅读。[自由浏览](assets/conversation-insights-issue-16-20261120/after-free-browsing.png) |
| 切段与重试 | 在第一段模拟下一段读取失败，原消息、阅读位置及 1 / 2 均保留。再次选择「下一段」可读到第二段。窄窗用「重试」也可到达该段，计数变为 2 / 2，「下一段」禁用。[切段失败](assets/conversation-insights-issue-16-20261120/after-next-fragment-failure.png) |
| 迟到的响应 | 在 960 × 640 窗口关闭仍在读取的引用，随即打开另一处引用，再释放第一次读取。窗口保留第二处原文。另一次回放先挂起前一页，再用键盘切段，释放旧分页后核对整份可见消息编号列表，仍是新片段的内容。[第二段及阅读焦点](assets/conversation-insights-issue-16-20261120/after-narrow-second-fragment.png) |
| 关闭与删除 | 从长报告底部打开原文，按 Escape 后报告滚动位置与打开前一致，焦点回到原链接。若在加载期间删除会话，则显示报告列表空态并聚焦列表标题。原链接收到 0 次焦点事件，迟到响应未重开弹窗。单独删除同名报告时，剩余报告的独有判断在重启后仍可回查。 |

在存储层另用两份合成报告验证异常引用。向其中一份已保存报告注入空片段、重复编号及指向其他会话的映射后，报告列表仍可打开，两份正文及有效引用都可读取。异常编号返回不可定位，若正文摘要不匹配则返回过期。新报告在保存前仍拒绝空片段。组件测试确认，点击无法定位的经历只显示错误提醒，焦点留在报告内。

## 窄窗与焦点修复

1. 基线通过原有 2 个桌面用例。新增用例复现首读等待时提前显示 1 / 2，同尺寸截图中长会话名还把关闭按钮挤出了窗口。[修复前](assets/conversation-insights-issue-16-20261120/before-narrow-loading.png)
2. 第一轮调整后，关闭按钮已可见，但引用短语藏在标题滚动区内。同期桌面回归 3 项通过、1 项失败，记录到删除后的旧链接短暂获得 1 次焦点。原生对话框关闭时自动还焦点，单靠清空应用保存的链接引用仍会触发它。[中间版本](assets/conversation-insights-issue-16-20261120/review-narrow-hidden-phrase.png)
3. 会话名最多占两行，悬停可读全名；短语独立排在下方。首读等待时关闭按钮有焦点，定位成功才显示计数。失效入口随报告卸载时直接移除模态层。4 个定向桌面用例复验通过，覆盖关闭、重试、删除和迟到响应。[修复后](assets/conversation-insights-issue-16-20261120/after-narrow-loading.png)

## #40 审查修复

- 后端回归注入两份合成报告。将其中一份「关于你」的引用编号改为空格，将「你们的相处」的一处编号改为 129 个字符。修复前整批列表读取失败。修复后两份报告和正常引用均可读取，损坏的两处仍可点击并提示无法定位。新生成的报告含无效编号时仍会被拒绝保存。
