# 长聊天候选更新与回读对照

对应[想法004](../planning/ideas/004-conversation-insights.md)。用户在上一轮未触发额外回读后，明确要求继续使用原模型，换更长、跨多批次的聊天验证自然候选更新、撤回及回读收益，禁止人为强制触发。沿用本机chatgptPRO的gpt-6.1-sol、不设金额上限的授权；本轮实际派发最多64次，与历史轮次分开记账。只发送新的合成聊天，不读取真实会话，不修改安装版或发布远端。

## 调用前固定的设计

从本地提交1328f4e继续，远端main为6910b80，fetch及pull后无落后提交。产品阅读、核查指令和实现保持不变。扩展已有试验工具，不引入新框架或付费服务。

固定两组合成材料，各120条，分布在10个日期段，含自然连续的多个话题。材料文件为`tests/quality/insight-long-comparison-material.mjs`。首次模型调用前完成全文、事实标准与材料摘要值的保存；不根据模型是否触发候选修改文字、删阅读记录、注入候选、修改回复关系或缩小容量。

- **筹备分工。** 本人承担显眼的现场筹备后概括长期负担，其他日期的分工及后文说明使这一概括需要限定或撤回，同时保留真实疲累与未定的下一次安排。
- **条件改期。** 早期约定包含多个条件，后续只放宽其中一项，并另行授权海报采购；较晚发生的实际改期需要区分仍生效的条件与独立授权。

上述为试验设计，并非已观察到的模型表现；准确的来源编号和评分事实在材料定稿后补入下节，先于调用冻结。6—10个阅读批次是估计，不硬切消息；实际按产品容量打包，包括必要分片、相关旧原文补充和导航压缩。

### 共享阅读与比较方法

1. **通读。** 按产品流程阅读全部材料，首次进入核查前冻结检查点。记录每个批次实际原文、已知候选、模型新增候选与更新动作；用稳定编号追踪，不把普通笔记变化算作候选更新。
2. **按需核查。** 从同一检查点恢复，由模型决定是否核查、展开笔记、取回原文、结束或保留未知。产品成稿使用统一试验指令，正文各节最多两段，输出上限3000词元。
3. **直接分析。** 使用按需方法实际成稿时的共同观察、未决事项和时区；候选换回通读结束状态，不接收随后核查的判断或新原文。使用相同成稿指令及输出上限，一次成稿。
4. **带已读摘录的直接分析。** 仅在按需方法实际派发了包含原文的核查请求时运行。一次成稿，额外提供通读结束时已保存、已验证的逐字摘录及其原文作者、日期、回复关系，不取回新原文、不使用核查新增摘录。这一较强对照检查收益是否只是重新拿到已有摘录。所有合法冻结摘录按来源编号及逐字内容去重后完整提供；没有摘录则不追加同输入调用，超出容量则记录失败，不选择性裁剪。两种情况均不能作为按需更优的证据。

三个成稿方法均可依据实际给出的来源笔记分析；候选本身不是已证实事实。最终结构化人格判断固定为空，仅比较正文事实、未知及引用。两主方法共享底稿摘要值须一致。已解决候选的有效判断可被直接方法使用，不把它们人为撤回。

长材料不另跑全文一次分析：本机模型配置未指定上下文容量，应用暂按16000预算，不能把未核实的服务容量当作已知能力。输入估算上限7000与上轮一致，用UTF-8文本保守计量，并非精确分词；所有方法守相同的成稿估算上限。不能通过容量失败后临时增大配置取得成功样本。

### 判定和停止条件

候选更新成立须同时有：真实阅读响应自然提出候选、后续批次实际收到同一编号、模型自行返回修订或解决、检查点状态相应变化。撤回需保留实际反例和仍成立的事实；没有候选、普通笔记改写或核查阶段才修改，均不算通读中的候选更新成功。

回读发生按实际外发请求中的原文判定，不按本地读取日志计数；恢复时本地加载快照不算模型回读。分别记录首次核查携带原文、模型主动再取的原文、导航摘要及此前已经保留的逐字摘录。源编号曾出现不表示该条件一直保留在后续输入中，反之已在共同笔记中的信息不能称为新发现。

回读收益须相较同底稿直接分析减少至少一个关键事实、条件或角色错误，或把影响判断的未知变成有原文支持的结论，且不增加关键错误或不受原文支持的引用。分别评分事实错误、重要遗漏/未知和语义引用错配，不把文风或篇幅当收益。带已读摘录的直接分析同样正确时，还须逐项核对改善所依赖的限定确实存在于冻结摘录或共同笔记，且引用支持该限定，才能说该例用已有证据即可做到；同分本身不能证明归因。若按需仍更好，也只能说明这条核查流程在该例更好，额外推理次数与原文作用尚未完全隔离。

每例生产流程总计最多28次请求，包含阅读、核查、成稿、格式修复和导航压缩；8个候选、每项4轮、400000输入词元、40000输出词元、20分钟有效时间；单次实际输出最多3000。直接方法各一次请求，各自使用冻结通读后的剩余预算。成稿不再另行修复或抽样；首次结果保留。两例常规至多60次，全部实际派发合计最多64次，余量仅供符合下述故障复测条件的运行，失败也计入，不通过新目录清零。共享阅读实际费用只记一次，独立方法成本另外合计展示。

达到两组固定比较后停止，不为了成功触发追加样本。无自然候选或回读时据实报告该路径仍未验证。出现材料越界、来源无效或预算不可执行立即停机；一般服务失败保留结果，成稿不额外抽样选优。产品故障如需修复，先保存失败证据和回归；修复后使用同一材料、同一剩余总账记录复测，不能覆盖旧记录。

## 实际结果

### 首次通读中断与修复

首组前两次真实请求均返回200，第2批后任务报`INVALID_EVIDENCE`并按预注册条件停机，尚未进入核查。两笔实际用量为3891输入、2018输出词元，保留在原`shared-workload-reading`目录，计入本轮64次账本。

具体原因是关闭未决事项与新增事实引用共用了原文白名单。第2批发出11—20条原文，没有附带9、10的全文，但明确给了引用9、10的未决事项文字。模型从11的已经吃到饭得出午饭事项已解决，返回关闭9、10，并将尚未确定的台灯后续另记为11、12；新观察和新未决事项均只引用11—20。程序却要求关闭标记也只能用11—20，误拒绝了合理状态更新。

修复仅允许关闭标记使用本批真正发出的旧事项编号；不允许未显示的历史事项编号，也不把这些编号开放给新观察、候选或新事项的事实引用。未改产品提示词、冻结材料或候选触发条件。最小回归修复前37通过1失败，修复后洞察生成38项通过，类型检查通过；独立审查确认这个边界不构成扩大证据权限或强制回读。

后续恢复须保留原失败目录、原响应与停机记录，继承原检查点的已用预算，从未完成的第2批重新请求；不重发已成功的第1批，不回滚总账。新的阅读结果单独保存，所有比较方法再共享同一个成功通读检查点。恢复前先完成工具的独立审查及离线检查。

独立审查还发现：可见与未显示的两个事项可能共用同一来源编号。补充修复使关闭可见事项不会连带删除未显示的同源事项；新增回归先失败，再随生成测试39项通过。实际恢复从11—20重新请求，原先1—10未重发，原2次派发与新17次均计入同一账本。[恢复说明](assets/conversation-insights-long-comparison-20261115/halt-resolution-01.json)和[原停机记录](assets/conversation-insights-long-comparison-20261115/shared-workload-reading/halt-before-resume.json)均保留。

**条件改期的具体问题。** 原文26放宽退款方式，61明确一年有效、无最低消费、可分次使用，62明确接受；两份报告却说授权对话没有原文，余额有效期和限制仍未确认。二者抓住了把局部许可扩大到改期的主线，但把已经有答案的条件重新写成未知；改期行动及截止时间的叙述大体正确，引用却缺少97、99、101、109、111等直接依据。

两个容易过度评分的边界单列：85表明收据内容已核对，但没有逐字确认照片发送，因此泛称收据交付未知属于不准确限制，不计硬事实错误；63是客服称余额已转、登录后可见，没有逐字确认本人实际登录核验，保留独立到账核验未知可以成立。不能因此把61、62已经明确的规则和同意也重新写成未知。

## 复现本轮流程

`node scripts/insight-quality.mjs --long-comparison --dry-run`为零请求预检，不打开配置数据库。沿用已授权的数据库、供应商和模型环境变量，各例按`reading`、`adaptive`、`direct`顺序运行。`direct-rich`仅在已派发核查原文且冻结通读有合法摘录时运行，否则零派发拒绝；原文与范围校验不放宽。

只在有经审查的阅读故障时，原样归档`halt.json`到原阅读目录的`halt-before-resume.json`并记录恢复依据，再执行`--long-comparison shared-workload reading --resume-reading`。续跑写入独立`reading-resume`目录，保留原失败记录和账本；冻结材料、模型版本、公开配置、预算、阶段及待读位置须匹配。恢复未完成时普通阶段仍被阻止。这个入口不自动解除停机，也不覆盖任何已存在结果。
