# 会话阅读与操作完善：修改方案及验收清单

> 状态：2026-10-31 已获授权并实施，当前行为、必要适配和验收证据见[实施记录](../../designs/whomi-conversation-reading-polish.md)。下文保留实施前方案及原始检查项，不将历史提议改写成已验证事实。
> 后续执行者：用户明确授权编码后，再使用 superpowers:executing-plans 或用户选定的执行方式；不得因读取本方案自动开始实施、提交或发布。

**目标：** 完成五项已评审问题，先改善回答排版与空间分配，再完善回答归属、统计和复制。

**结构：** 保留 Whomi 原文与 AI 并排的工作区，历史默认收起；复用 Cherry 的回答排版、模型身份和统计呈现能力，接入 Whomi 的已保存问答与模型版本。原文阅读、引用定位和输入草稿仍由 Whomi 管理。

**技术环境：** React 19、TypeScript、Electron 45；当前工程采用普通样式文件与 Radix 浮层。Cherry 的样式工具链和数据上下文需要适配，尚未证明其组件可以无改动装入本工程。

**需求依据：** 用户本轮明确选择；[现行设计约定](../../../DESIGN.md)；[已接入范围](../../research/cherry-conversation-reuse.md)；[本轮原始评审](D:/CodexData/visualizations/2026/10/31/01a18f64-6f47-7451-934e-8a48429063d7/critique/review.md)。本文件同时记录目标行为与实施前的验收约定。

## 已确认范围与基线

- 优先顺序：R01 回答排版 → R02 空间分配 → R03 模型身份 → R04 统计口径 → R05 复制回答。
- 普通桌面保持原文与 AI 并排，历史默认收起；不采用 AI 独占主区作为普通桌面的默认布局。
- 继续保留短气泡、引用定位、原文位置、当前草稿、失败重试和已保存历史。
- 实测对照是 Whomi 0.1.5 与 Cherry Studio 2.1.8；源码复用继续固定 Cherry 提交 `f19aa72f969b782ed72f81be80976b237ae26605`，其包版本为 2.1.9。两者不可表述为同一版本。
- 本轮阅读并刷新远端后的 Whomi 基线为 `main` / `origin/main`，本地领先两次提交，无落后；工作区起始干净。正式编码前仍须重新检查未提交改动、跟踪分支、远端 main 差异，按项目规则确认开发分支并拉取。
- 本轮不改模型服务配置页的密度，不扩展朗读、翻译、多模型并发、附件、工具或新聊天分支功能。

### 编码授权后的首个验证点

先在隔离开发入口接入上述排版组件的最小完整链，验证本方案的固定回答和流式片段能构建、渲染，并与 Whomi 主题共存。核对内部导入、样式入口、相关依赖及上游补丁，不能只复制入口文件后宣称完成复用。

通过条件：标题、列表、表格和未闭合流式片段正确；没有依赖 Cherry 的全局状态或服务；原始聊天不受影响。若必须引入与本轮无关的大块平台，停止该接入路径，列出直接依赖其底层现成组件的代价再确认。此验证本轮未执行，也不先安装依赖。

## 界面状态约定

| 状态 | 显示与保留 | 退出或下一步 |
| --- | --- | --- |
| 原文阅读 | 原文与既有工具 | 从顶部打开 AI |
| 首次打开 AI | 导航、原文、AI 三个区域；历史收起；输入区只出现一处 | 阅读、提问或主动打开历史 |
| 手动打开历史 | 建议采用 AI 区内的临时浮层，保持原文位置和回答宽度；此为本方案的具体组织建议 | 选择后收起；Escape 或外部点击关闭，焦点回历史按钮 |
| 正在回答 | 稳定的回答身份与逐步排版的正文；用户仍可写下一条草稿 | 完成、停止或失败；不重置草稿 |
| 完成 | 回答模型、结构化正文、轻量复制与统计入口 | 复制、查看用量或继续提问 |
| 停止或部分失败 | 保留已生成内容及真实状态；非空部分结果可复制 | 既有重试／继续路径；没有文字时不显示成功复制 |
| 窄窗口 | 当前 1000 像素及以下采用单区覆盖的兼容行为；普通桌面并排方向不变 | 关闭 AI 回原文，引用返回与阅读位置仍可恢复 |

空间处理先释放默认历史的约 180 像素。1280 × 800、主导航 240 像素时，保留现有约 38% 原文、62% AI 分配，AI 区由约 464 扩至约 644 像素；这些是布局核对值，不代表文字必须固定在某一行。首轮不新增拖拽分隔器或重做导航。窄窗兼容是本方案对并排方向的适用边界，后续验收必须单列。

## R01：长回答的真实排版

**场景：** 用户阅读示例解释，想按表格对应原文与观察。目前标题井号、列表连字符和表格分隔符直接进入正文。

**修改：** 新建薄的 `answer-content.tsx` 适配层，接收稳定回答编号、原始回答文本和生成状态。运行中使用 Cherry 的 StreamingMarkdown，终态使用对应稳定输出方式；标题、段落、列表和表格沿用源阅读层级，再映射 Whomi 主题。表格与代码块的溢出由局部区域承接。原文消息继续按纯文本呈现。

**预计文件：** `src/components/conversation-ai/answer-content.tsx`、对应样式、`workspace.tsx`、`package.json`、锁文件、所需迁入源文件及 `THIRD_PARTY_NOTICES.md`。实际依赖闭包以首个验证点为准，不在方案里虚构完成的文件清单。

**接口：** 建议 `AnswerContent({ id, text, status })`；只消费回答文本与状态，不能自行发模型请求或修改原文。沿用源模块的内容清理和链接限制，避免将模型返回的脚本或任意页面内容当作应用代码执行。

- [ ] C01：发送固定长回答，显示两个标题、三项列表、两列两行数据加表头；没有裸露的控制标记。
- [ ] C02：将标题、列表和表格分多次流式送达；已出现的正文不反复淡入，未闭合片段不让页面报错或丢失文字。
- [ ] C03：向上阅读时继续输出，不强行拉回底部；回到末尾后继续跟随输出。停止后文字保留。
- [ ] C04：长单元格、长链接和代码块不撑宽整个页面；窄窗可以读到最右侧内容；不执行文本中的脚本或危险链接。

## R02：并排阅读、历史默认收起

**场景：** 用户打开第一条 AI 对话后读长回答。当前宽屏默认显示只有一条记录的历史列，回答被挤窄。

**修改：** `threadListOpen` 初始为 false。普通桌面保持原文与 AI 并排；手动历史采用上表中的临时展开方式，关闭不卸载当前问答。宽度变化不能清空草稿、引用或滚动位置。标题工具和系统窗口控制继续各自可点击。

**预计文件：** `workspace.tsx`、`workspace.css`、`workspace-refinements.test.tsx`、`tests/desktop/ai.spec.mjs`。

- [ ] C05：1280 × 800 首次打开 AI，只见导航、原文、AI，历史按钮为收起状态；释放空间归给回答。
- [ ] C06：打开历史，切另一条，再回原对话并关闭历史；两条对话的草稿、引用和已保存内容各自保留，原文阅读位置不动。
- [ ] C07：鼠标与键盘均可打开和关闭历史；Escape 后焦点回触发按钮。展开态不遮挡系统关闭控件。
- [ ] C08：960 × 800 和 360 × 800 沿用窄窗兼容方式；关闭 AI 可回原文，输入、发送、模型和重试入口可达。恢复到 1280 后仍能正常并排阅读。

## R03：逐条回答显示实际生成模型

**场景：** 用户用甲得到回答，再把下一次模型切成乙。当前旧回答只标 AI，来源需要打开统计才能确认。

**修改：** 沿用 Cherry 的逐条模型署名。数据库已有 `ai_turns.model_version` 与 `ai_model_versions`，优先据此增加只包含显示所需字段的响应身份，而不是新建一套模型快照表。建议在 `AiTurn` 与恢复对象增加可选 `modelIdentity: { id, version, label, model }`，向前端传递该轮版本名称和调用标识；不传密钥、地址或整个凭据对象。回答标题和统计标题使用同一身份。

已有版本记录没有服务商历史名称；本轮不承诺补造历史服务商快照。无法读取旧身份时展示已知调用标识或明确未知，不能回退成当前输入区选中的模型。新请求在后端回执前可以显示提交时捕获的身份，不能从变化中的全局选择实时取值。

**预计文件：** `src/shared/ai-contract.ts`、`electron/data/ai/repository.ts`、`src/data/conversation-ai-client.ts`、`conversation-ai/types.ts`、`workspace.tsx`；对应后台、适配器与界面测试。

- [ ] C09：甲生成 → 切乙 → 乙生成；两条回答分别显示甲、乙，输入区只表示下一轮选择。
- [ ] C10：修改甲的显示名或停用甲后重开历史，已有回答仍使用生成时版本身份；同名不同模型可通过完整提示辨认调用标识。
- [ ] C11：重启恢复后标题与统计身份一致；旧身份缺失时不冒充乙，也不使整个历史无法打开。

## R04：统计摘要与详情共用模型生成速度

**场景：** 用户看到摘要每秒 287.2，打开详情却看到主项 389.3，无法直接对上数字。

**修改：** 让摘要与详情第一层都消费 `messagePerformance(usage).modelTokensPerSecond`，共用一位小数格式。端到端速度保留在详情。保留缓存输入口径及未知值显示；不修改存储中原指标的含义，不增加统计常识段落。

**预计文件：** `workspace.tsx`、`message-performance.ts` 及其测试、`cherry-workspace.test.tsx`。

- [ ] C12：合成输出 100、总耗时 10 秒、首次输出等待 9 秒，摘要与详情主项均为每秒 100，端到端为每秒 10。
- [ ] C13：缺少首次输出时间或生成时长不大于零时，摘要不伪造模型速度；详情未知值仍为横线，已知输出继续显示。
- [ ] C14：输入 1240、输出 286、缓存读取 240、未缓存 1000 一致保留；失败无用量时不补零。

## R05：就近复制完整回答

**场景：** 用户读完观察想保存到笔记，当前需要跨滚动区域拖选，容易漏掉末尾表格。

**修改：** 在回答底部的轻量操作行加入复制，复用 Cherry 复制反馈流程。建议复制原始 Markdown 文本，以保留标题、列表与表格数据；这与复制屏幕中附带模型名和统计的文字区分开。只有复制成功才显示已复制，失败显示可重试的简短反馈。

**预计文件：** 建议新增 `answer-actions.tsx`，接收 `text` 和是否可复制；`workspace.tsx` 和对应样式接入。复用项目现有 `navigator.clipboard.writeText` 及已有限制，不扩大剪贴板读取权限。

- [ ] C15：点击复制后粘贴到隔离测试文本框，内容等于该条回答原文；标题、三项列表、表格两行齐全，没有模型名、用量或下一条问题。
- [ ] C16：停止或部分失败且有正文时能复制当前结果；没有正文时不显示可成功复制的入口。
- [ ] C17：剪贴板写入失败时不显示成功；用户可再次点击，正文和草稿不变化。键盘可触达，成功反馈可被辅助技术读取。

## 固定验收材料与完整流程

所有数据为合成示例。正常比较使用同一问题：`这段示例里，我怎样回应了朋友？`。原文四条为朋友担心准备不完、本人追问卡住部分、朋友说开头不顺、本人约明晚九点并询问希望听建议还是倾诉。

固定回答保存于 [阅读验收输入](../../designs/fixtures/conversation-reading-acceptance.md)。普通窗口为 1280 × 800，窄窗口为 960 × 800 与 360 × 800；记录实际缩放、主题、版本与滚动位置。不能靠更换成更短回答使截图通过。

- [ ] C18：从已有模型配置出发，选甲 → 发送长问题 → 读完标题列表表格 → 复制 → 展开统计 → 切乙读旧回答 → 打开历史切换后返回 → 触发失败 → 写下一条草稿 → 重试 → 关闭 AI 回原文。
- [ ] C19：重复上述链条的相关窄窗步骤，验证模型菜单与统计浮层不被裁切，草稿、引用和原文位置保留。
- [ ] C20：在当前窗口只保存一个有效输入区；流式完成、失败或重试均不重新填回已发送问题，也不覆盖后续草稿。

每项保存修复前、修复后、Cherry 参考图；编号采用 `C01-whomi-after-1280x800.png` 等可追溯名字。报告逐项写通过、未通过或未验证。参考图沿用本轮原始图并记录其版本；新增运行需补当次版本，不能混称同一基线。

## 执行顺序与检查规模

1. R01：最小复用验证通过后完成排版，先锁定内容语义和流式行为。
2. R02：以同一长回答核对三栏初始状态、手动历史与窄窗，再接受阅读布局。
3. R03：贯通后端历史模型身份到回答与统计，检查刷新、改名和恢复。
4. R04：用有明确数学结果的合成输入统一统计显示。
5. R05：接入复制，最后重走 C18～C20 的完整任务链。

针对这些行为增加必要回归，避免只断言元素存在。先跑对应前端测试；R03 跑相关后台与适配器测试；桌面验证运行现有隔离入口。正式交付前执行类型检查、桌面构建和受影响桌面流程。无新变更或失败时不重复扩大测试范围。

本方案没有执行上述产品检查，所有复选项保持待验。后续应由未参与实现的评审者按同一场景复核；自动扫描零发现不能关闭验收项。
