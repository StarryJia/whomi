## 开发顺序与逐项验收

### 第一阶段　修复试用时能直接遇到的六处问题

| 顺序 | 开发内容 | 达标时可以观察到什么 |
| --- | --- | --- |
| 1 | AI 引用整组高亮 | 按截图的 **19 条**验收。点击引用时定位首条，滚动或分页后仍能认出全部被引用的消息，中间未引用的消息保持原样。重启后重开这条引用仍可核对。单条聊天消息的引用跳转和返回照常可用。 |
| 2 | 两类会话管理中的 AI 历史 | 历史条目右键可置顶、取消置顶和删除，可拖动排序。重启保留置顶和顺序。阅读 A 时操作 B 不切走 A，也不丢草稿。删除 B 只清理该 AI 对话，原始聊天与其他 AI 对话仍可打开。 |
| 3 | 两类会话管理中的原始会话 | 移除主侧栏「管理会话 · 未开放」，保留导入 `＋`。会话行提供同样的右键菜单与拖动排序，复用已有删除确认，说明会清理该会话的原文、关联 AI 对话与成稿。取消后条目和阅读位置保留；确认后相关记忆和总览贡献同步移除。 |
| 4 | 简化个人总览空状态 | 去掉解释页面用途的文案。空库可进入导入，已有记录可打开真实会话，已有记忆可查看对应成稿。用三种数据状态核对入口。 |
| 5 | 回答状态移到 AI 图标下方 | 发送问题后，「正在回答…」在本条回答的图标下方左对齐。正文出现后收起等待提示；失败和重试位于对应回答内。宽窗、窄窗分别核对。 |
| 6 | 桌面分栏可拖宽 | 优先做「原文 ↔ AI 对话」和「服务商列表 ↔ 配置详情」，其次做「主导航 ↔ 正文」。三处分开记住宽度，双击分隔线恢复默认。拖窄时两侧主要操作仍可用，窄屏沿用覆盖或单页布局。 |

**代码入口**　引用定位在 `src/components/conversations.tsx` 的 `jumpToReference`，当前只读引用中的第一条。该文件也已有原始会话删除确认。AI 历史和回答状态在 `src/components/conversation-ai/workspace.tsx` 与同目录 `workspace.css`。列表操作可参考[Cherry 设置复用记录](../../research/cherry-settings-reuse.md)里的行级菜单。把置顶和排序接入桌面存储时，核对既有数据、失败回滚和重启读取。服务商分栏从 `src/components/settings/model-services.tsx` 入手。

### 第二阶段　接通记忆生成、仓库和文稿

7. **从原会话生成，到仓库阅读。** 在聊天页点「整理成记忆」，核对范围和模型后点「生成记忆」。在原位置显示进度和「暂停生成／继续生成」；取消确认不启动任务。完成后点「查看记忆」，转到带收纳盒图标的「记忆仓库」，根据任务编号直接打开这份文稿。也能从仓库列表点开任一成稿，关闭后回到原条目。如果同一会话有两份成稿，两个入口都应能打开正确的一份。列表的最终排序或分组选项如需定版，只确认这个局部决定。[记忆功能规范](../../designs/whomi-memory-library.md) · [可交互样稿](../../designs/previews/memory-library/index.html)
8. **按完整事件生成统一文稿。** 每次生成任务只产出一份《我们的记忆》。标题下单独出现一次娱乐声明，正文使用三个无编号标题「MBTI 预测」「我们的记忆」「我们的关系」。MBTI 指迈尔斯–布里格斯性格类型指标，只预测已确认的本人；第二节概括讨论分量最大的共同经历，第三节写模型对相处方式的看法。正文不展示消息编号、逐条依据或人格分数。例如搬家在第一批聊日期、第三批聊同一次搬家的货车，最终只讲一件事。旧成稿按原样读取，旧暂停任务沿原版本续完；重试或继续不会多出一份成稿。

**代码入口**　`src/App.tsx` 管导航，`src/components/conversation-ai/use-analysis-task.ts` 接任务状态；`electron/main/ai-service.ts`、`electron/data/ai/prompt-version.ts`、`electron/data/ai/repository.ts` 分别涉及模型请求、生成指令版本和任务结果存储。复用本人确认、原文快照与已提交批次，给新文稿独立版本。验收时，用虚构的 24 条消息在已保存 8 条时暂停，重启后从 8/24 继续，再从仓库读到本次成稿。

### 第三阶段　让单份预测进入个人总览

9. **逐维汇总本人在各段关系中的表现。** 四维都能判断才显示完整类型；只判断出安排偏好时，文稿可显示「J · 偏好提前安排」「其余维度暂难判断」；只交换地址时显示「暂难判断」，后两节仍可阅读。每份记忆只给有材料的维度贡献方向。总览已有未知、倾向和均衡的展示状态，接入真实结果时保留它们的区别。见[个人总览设计](../../designs/whomi-self-understanding-design.md)、[总览数据类型](../../../src/components/overview/types.ts)。

**建议的算法，待小样验证。** 模型在归并后的事件中识别本人表现，区分本人发言、引用和对方意见。同一事件每一维最多贡献一次，取材覆盖所有有效事件，包括最后没有写进正文的小事。程序先算每段关系的各维观察，再在本地汇总。候选参数包括单维至少 3 件有效事件、同一方向占三分之二、总览至少两段关系并等权。以上均未定版，不能当作准确率或发布门槛。

**最小验证和决策点。** 向用户提交一小组虚构中文对话的验证方案，经同意再试算法。至少覆盖三类输入：有明确选择、受外部要求照做、只有对方表达偏好。再交换双方身份、改变分片位置、对同一会话重复生成。分别报告每维能判断多少、误把对方算给本人几次、该留白却强猜几次。若分片或重复生成改变贡献，先修归属或去重，再比较门槛。其他已确认任务可先行开发。

**总览更新验收。** 同一原始会话重生成成功后只替换该会话的贡献，历史成稿仍可阅读；暂停、失败不覆盖上次完整结果。删除原始会话或更正本人时撤回失效贡献。一份全为「暂难判断」的新记忆不会冲掉其他关系已有的倾向。打开总览从本地读取结果。

## 交付前走一遍

- 先用相同虚构聊天核对 19 条引用、两类删除的影响范围、拖序重启、三个分栏、三种总览状态，再走「生成 → 暂停 → 重启 → 继续 → 查看记忆 → 返回仓库 → 打开总览」。每个阶段留正常、取消或失败重试、窄窗的关键截图，标清设计样稿与正式应用实测。
- 做类型检查和对应回归。可从 `npm run typecheck`、`npm test`、`npm run test:backend` 开始。桌面测试前先 `npm run desktop:build`，再 `npm run test:desktop`，确保跑的是新代码。重点复用 [19 条引用相关的既有跳转测试入口](../../../tests/desktop/acceptance-fixes.spec.mjs)、[阅读回归](../../../tests/desktop/reading-polish.spec.mjs)、[续跑测试](../../../tests/backend/analysis-continuation.test.ts)、[桌面重启恢复](../../../tests/desktop/analysis-resume.spec.mjs)和[预置服务商测试](../../../tests/desktop/provider-presets.spec.mjs)。19 条整组高亮属于需新增覆盖的场景。
- 通过后运行 `npm run desktop:dist` 生成 Windows 安装包，在 `release/` 核对新文件并提供绝对路径。交付时列出已验证、仍待决定或未通过的项目、截图和中文提交说明。本地交付即可，推送、发布和拉取请求需另获明确授权。
