# 问一问 Implementation Plan · 独立需求与选型阶段

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为问一问建立独立交付计划，先明确提问方向和理解更新方式，再确定需要实现的问答及检索能力。

**Architecture:** 当前问一问是澄清疑问的前端，正式应用尚未接问题生成与持久化。优先评估复用现有页面、ClarificationAdapter 和模型运行器；与心事屋共用的检索资料范围及删除规则在选型阶段统一设计，不让对话洞察依赖该建设。

**Tech Stack:** 已有 React、Electron、SQLite、模型运行器；检索与嵌入模型待比较，不预选新后台服务。

**Spec:** [005 主记录](../../planning/ideas/005-ask.md)；本计划仅覆盖需求、调研与实施计划产出，不能直接用于问答功能编码。

## Global Constraints

- 2026-11-13 用户要求将问一问作为独立计划安排；不并入首期对话洞察实现。
- 不把现有澄清页面假定为已实现通用用户问答，不自行承诺每日问题数量。
- 检索增强生成是候选能力，先明确允许读取的会话、报告与回答资料，旧判断不得冒充原文证据。
- 新页面按 design-shotgun 出图并选定后进入实现；试验模型、数据与费用须具体约定。

- 界面工单必须使用 impeccable 制定视觉约束、ui-ux-pro-max 核对交互和适配、design-review 在实现后审查真实页面；设计图确认不等于运行验证。逐页讨论并确认设计后再进入下一页。

## Review Focus

在需求与选型产物中逐项覆盖：提问方向；答案持久化与撤回；来源引用可回查；没有相关材料时的行为；来源删除后的检索失效。

**Interfaces:** 当前 ClarificationAdapter.submit(questionId, answer) 与 withdraw(questionId, answerId)；设计阶段决定继续沿用还是扩展，不预先发明问答接口。
