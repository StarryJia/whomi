# 会话 AI 后端实施计划

依据：[已讨论方案](../specs/2026-10-30-conversation-ai-backend-design.md)。用户于本轮授权按方案完成后端开发，沿用当前 main；基线 36f8136，跟踪 origin/main，领先12、落后0，工作区干净。开发前完成 fetch 和 pull。

## 范围和复用

复用完整 Pi 软件开发工具包、现有 Electron 窗口校验、独立数据进程、SQLite、稳定消息编号与已确认本人身份。新增受控 Agent 进程与业务任务服务。先验证锁定 Pi 版本加载、取消、会话检查点与受控资源，不更改 Pi 核心。

使用虚构消息和本地可控模型传输；不读取个人 Agent 配置，不请求付费模型。首期接入 Pi 支持的 OpenAI 兼容文本协议；实际服务兼容性必须分别验证。凭据经操作系统加密后保存，页面不可读回。

用户已授权的实施默认：每会话独立 AI 线程；关闭侧窗仅隐藏，显式停止才取消；结果入口按任务标识；个人总览全局画像自动聚合仍不实现。分析结果为有原文编号依据的观察、总结与限制，不引入未经验证的人格计分。分析管理、技能商店、外部插件和全库原文读取不做。

## 文件职责与顺序

1. `src/shared/ai-contract.ts` 定义正式请求、快照和事件；`electron/data/ai/` 管理版本化模型、确认快照、线程、批次、报告、用量和恢复。schema 升级保持原文不变，写入复用数据进程写队列。
2. `electron/agent/` 封装锁定版本 Pi 及进程通信；只加载明确提供的指令、画像、引用和已登记技能，不自动发现宿主配置、扩展、命令或文件工具。原生会话检查点只在本应用目录。
3. `electron/main/ai-service.ts` 调度确认、批次、任务与尝试；校验版本及归属，停止后忽略晚回调，已提交批次可恢复；`ai-host.ts` 管理 Agent 进程。
4. `electron/main/index.ts`、preload 增加独立 AI 调用与事件通道，保留可信窗口检查；`src/data/conversation-ai-client.ts` 接真实适配器，前端分析按钮使用后端确认凭据，正式请求只传原文编号，不信任页面正文和历史。
5. 文档记录运行配置、实际验证和边界，执行前端/后端完整测试、类型、网页和桌面构建及合成本地模型集成验收。

## 每项的测试顺序

每项先写行为测试并运行确认失败，再实现最小代码，通过后继续。存储使用真实临时数据库；模型边界使用可控流。核心验收：取消确认零任务；重复提交去重；跨会话引用拒绝；导入追加不改变快照；失败重试用量累计而覆盖不重复；报告写入失败不完成；中断不自动重算；身份变化失效；用户技能不进入分析；未知用量不补零；具体任务报告可读取；迁移失败回滚。

## 实施记录

- 基线核验完成；锁定 Pi 官方发布版 1.4.0，完整 SDK 在 Electron Agent 进程加载，使用自定义空资源加载器而非默认目录发现。
- 数据任务层完成：版本 4 迁移、单写入队列、模型版本密文、分析凭据、批次与报告、线程及用量、重启恢复。身份与提示词版本变化阻止混合续算。
- 调度与桥接完成：正式请求只传消息编号；分析、对话及事件按窗口归属；停止保留已生成文字，重试不重复提问；离页解除观察。
- 独立审查提出并修正：停止立即重试竞态、排队身份重查、宿主默认资源发现、缓存计量、长对话预算、分层汇总、提示词版本。各项有先失败再通过的行为测试。
- 决策说明：长对话超预算时保留数据库全量记录，仅重建供模型使用的近期完整问答，不执行 Pi 自动压缩或隐藏额外请求；极端单次输入仍要求减少引用。用户界面重新分析创建新任务，后台另保留明确的继续接口。
- 最终验证结果与范围见[验收记录](../../research/conversation-ai-backend-validation.md)。
